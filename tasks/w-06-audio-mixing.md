# W-06 원본음·음악 믹싱

- 상태: 완료
- 구현 계약: [DESIGN-0008](../docs/design/design-0008-audio-mixing-contract.md)
- 완료일: 2026-09-11

## 작업 목표

현재 목업으로 남아 있는 영상 원본음과 배경 음악을 실제 프로젝트 상태, FFmpeg 기반 오디오
처리와 재생 가능한 미리 듣기에 연결한다. 클립별 음량·음소거, 음악 배치·트리밍과 영상 재생
속도를 하나의 결정적인 오디오 그래프로 해석하고, W-07 출력이 같은 그래프를 재사용할 수 있게
한다.

이 작업을 완료하면 사용자는 실제 영상 소리와 음악을 들으면서 위치와 음량을 편집할 수 있어야
한다. 내레이션 녹음, 파형, 페이드, 자동 더킹과 시각 효과는 이 작업의 범위가 아니다.

## 사용자 결과

- 영상 클립별 원본음 음량을 `0~100%`로 설정할 수 있다.
- 음소거를 켰다가 해제해도 이전 음량 값이 보존된다.
- 오디오 미디어를 고정 음악 트랙에 추가하고 절대 시작 위치를 지정할 수 있다.
- 음악의 source in/out, 타임라인 시작, 음량과 음소거를 편집할 수 있다.
- 재생·일시 정지·탐색 직후 현재 프로젝트 위치와 맞는 실제 오디오를 듣는다.
- 미리 보기 음소거는 세션 상태이며 프로젝트의 저장된 음량 값을 바꾸지 않는다.
- 사용할 수 없는 오디오 스트림이나 장치 오류는 원인과 다음 행동을 표시한다.

## 프로젝트 모델과 저장 요구사항

- 오디오 편집값은 목업 모델이 아니라 `Project` 그래프에 저장되는 타입이 있는 값이어야 한다.
- 음량은 유효 범위가 명확한 결정적 값으로 표현한다. 부동소수점 누적 오차가 프로젝트 시간이나
  직렬화 결과에 들어가지 않게 한다.
- 음소거와 음량은 별도 값이다. 음소거가 음량을 0으로 덮어쓰는 방식은 허용하지 않는다.
- 원본 영상 소리 설정은 해당 시각 클립과 함께 이동·분할·트리밍·복제된다. 분할 결과는 기존
  설정을 보존한다.
- 음악은 고정 음악 트랙에서 프로젝트 절대 시간을 사용한다. 시각 클립 리플 편집이 음악
  시작 위치를 암묵적으로 바꾸지 않는다.
- 프로젝트의 재생·출력 길이는 시각 스토리 라인의 길이를 기준으로 한다. 그 범위를 벗어난
  음악 구간은 미리 보기와 출력에서 사용하지 않으며 시각 편집 길이를 늘리지 않는다.
- 모든 오디오 속성 변경은 하나의 사용자 적용 행동당 하나의 `ProjectCommand`로 실행되고
  undo/redo 왕복과 실패 원자성을 보장한다.
- 기존 프로젝트 파일을 안전하게 읽을 기본값과 호환 경계를 정의한다. 호환 가능한 선택 필드로
  표현할 수 없다면 스키마 마이그레이션을 함께 구현한다.
- 선택, 재생 위치, 오디오 장치와 디코딩 버퍼는 프로젝트 JSON에 기록하지 않는다.

## 오디오 그래프 요구사항

- 프로젝트 위치를 source 위치로 바꿀 때 W-05의 source in, 재생 속도와 반열린 구간 계약을
  그대로 사용한다.
- 영상 원본음은 실제 영상 파일의 오디오 스트림을 명시적으로 선택한다. 오디오 스트림이 없는
  영상은 오류가 아니라 무음 소스로 처리한다.
- 음악은 source in/out과 타임라인 시작을 정확히 반영하고 프로젝트 시작 전이나 끝 이후의
  샘플을 만들지 않는다.
- 서로 다른 샘플률·채널 구성을 공통 출력 형식으로 정규화한 뒤 믹싱한다. 클리핑을 방치하지
  않고 일관된 합산 또는 제한 정책을 둔다.
- 영상 재생 속도는 영상 시간과 원본음 시간을 함께 변경한다. 지원 범위를 벗어난 속도나 현재
  FFmpeg 빌드가 처리할 수 없는 경우 조용히 다른 결과를 만들지 말고 제한을 안내한다.
- 공통 그래프 작성 코드는 UI, 실시간 미리 듣기와 W-07 내보내기에서 재사용할 수 있는
  UI 독립 서비스여야 한다.
- FFmpeg 경로, 스트림 인덱스, 필터 값과 입력 경로는 argv 또는 안전하게 이스케이프된 필터
  구성으로 전달한다. 사용자 값을 셸 명령으로 실행하지 않는다.

## 미리 듣기와 동시성 요구사항

- 오디오 처리와 외부 프로세스 대기는 Qt UI 스레드에서 수행하지 않는다.
- 재생, 일시 정지, 탐색, 프로젝트 편집, 프로젝트 교체와 창 종료가 오디오 작업을 즉시
  중단하거나 새 세대로 교체한다.
- 연속 탐색에서는 최신 요청만 들리며 오래된 디코딩 결과가 뒤늦게 재생되지 않는다.
- 영상 프레임과 오디오가 같은 단조 시계와 `ProjectTime` 위치를 사용한다. 장시간 재생에서도
  타이머 간격을 누적 시간으로 오해하지 않는다.
- 테스트에서 실제 오디오 장치를 요구하지 않도록 출력 장치와 프로세스 실행기를 주입할 수
  있어야 한다.
- 종료 시 프로세스, 작업자, 오디오 버퍼와 장치를 제한 시간 안에 정리한다.

## 오류 계약

최소한 다음 상태를 구분한다.

- 원본 파일 누락
- 오디오 스트림 없음에 따른 정상 무음
- FFmpeg 또는 필요한 필터 없음
- 지원하지 않는 코덱·속도·샘플 형식
- 디코딩 실패 또는 제한 시간 초과
- 오디오 출력 장치 없음·열기 실패
- 취소 또는 오래된 결과 폐기

취소는 사용자 오류로 표시하지 않는다. 실패해도 프로젝트, 행동 이력, dirty 기준, 저장 파일과
원본 미디어는 변하지 않아야 한다.

## UI 요구사항

- 기존 속성 패널의 원본음·음악 음량, 음소거, 시작 위치와 사용 구간을 실제 명령에 연결한다.
- 목업으로 표시되던 오디오 관련 배지와 문구를 실제 상태로 교체한다.
- 오디오가 없는 영상, 누락 원본과 장치 실패를 서로 다른 상태로 표시한다.
- 재생 버튼과 `Space`, 탐색 슬라이더, 타임라인 재생 헤드와 오디오 위치가 같은 컨트롤러를
  사용한다.
- 미리 보기 음소거의 화면 상태는 저장된 프로젝트 음소거와 명확히 구분한다.

## 필수 자동 검증

- 음량 경계, 음소거 보존, 속성 명령의 undo/redo와 저장·열기 왕복
- 영상 분할·트리밍·속도 변경 뒤 원본음 설정과 source 시간 일치
- 음악 배치·트리밍과 프로젝트 밖 구간 절단
- 서로 다른 샘플률·채널 수와 여러 소스의 결정적인 믹싱
- 오디오가 없는 영상의 정상 무음 처리
- FFmpeg argv와 공통 필터 그래프의 시간·스트림·음량 매핑
- 재생·일시 정지·탐색·연속 탐색·편집·종료 시 취소 및 오래된 결과 폐기
- 주입한 시계와 오디오 출력으로 검증한 영상/오디오 위치 일치
- 모든 오류 경로에서 프로젝트·이력·dirty·원본 파일 불변
- W-01~W-05 및 기존 Qt UI 전체 회귀

실제 FFmpeg 통합 검증에는 짧은 다중 샘플률 테스트 미디어를 실행 중 생성하고, 결과 파형이나
샘플 위치를 기계적으로 비교한다. 테스트 미디어는 원본 불변성도 해시·크기·수정 시간으로
확인한다.

## 문서와 완료 조건

- W-06의 실제 모델, 그래프, 동시성, 오류와 저장 호환 계약을 새 순번의 `DESIGN` 문서로 남긴다.
- 문서 지도와 README의 개발 상태를 실제 구현 결과에 맞게 갱신한다.
- 목업 오디오 경계를 실제 서비스로 교체하고 아직 남은 기능을 실제처럼 표시하지 않는다.
- 집중 테스트와 전체 pytest, Ruff, strict mypy, 애플리케이션 점검이 모두 통과한다.
- W-07이 UI 코드나 목업 상태에 의존하지 않고 공통 오디오 그래프를 사용할 수 있다.
