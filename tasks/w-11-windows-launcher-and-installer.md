# W-11 Windows 네이티브 런처와 설치 흐름

## 작업 목표

Windows 사용자가 터미널 없이 잠긴 uv 환경과 FFmpeg 상태를 확인하고, 필요한 경우 명시적으로
구성·복구한 뒤 애플리케이션을 시작할 수 있는 작은 네이티브 GUI 런처를 제공한다. 설치,
명시적 업데이트와 제거는 자신이 등록한 파일·바로가기·선택적 PATH·파일 연결을 추적하고
되돌릴 수 있어야 한다.

## 선행 상태와 필수 계약

W-01~W-10이 완료된 상태를 전제로 한다. 구현 전에 다음 문서를 확인한다.

- [Python·uv·네이티브 런처 ADR](../docs/decisions/adr-0001-python-uv-native-launcher.md)
- [라이선스와 출력 권리 정책](../docs/policies/policy-0001-licensing-and-output-rights.md)
- [기능 인벤토리의 `F-RUNTIME-01`~`06`](../docs/product/product-0002-feature-inventory.md#f-runtime-실행-환경과-배포)
- [런타임 화면 기준](../docs/design/design-0001-screen-layout.md#s-runtime-windows-실행-준비와-진단)
- 현재 `scripts/environment/`의 Windows·Linux 점검, 설정과 실행 규약

Windows 런처는 기존 명령행 실행 경로를 대체하지 않는다. Python 애플리케이션 로직, 미디어
편집 로직과 환경 의존성 해석을 런처 안에 복제하지 않는다.

## 런처 사용자 결과

- 런처를 열면 준비되지 않음, 준비 중, 준비됨과 복구 필요 상태를 구분해 볼 수 있다.
- uv, 고정 Python, 프로젝트 환경과 FFmpeg/ffprobe의 상태 및 해결 행동을 확인할 수 있다.
- 사용자의 명시적 동의로만 환경 구성 또는 복구를 실행한다.
- 준비된 상태에서 프로젝트 파일이나 앱 옵션과 함께 편집기를 실행할 수 있다.
- 실패 시 이해 가능한 요약, 종료 코드와 진단 로그 위치를 확인할 수 있다.
- 환경 구성과 앱 실행을 취소하거나 창을 닫을 때 자식 프로세스가 고아로 남지 않는다.
- 고급 인자에 공백, 유니코드와 따옴표가 있어도 원래 argv 경계가 보존된다.

## 환경 점검 요구사항

- 런처 자신의 설치 또는 실행 위치에서 앱 루트를 결정하고 필요한 파일의 절대 경로를 만든다.
- `uv` 실행 가능 여부와 지원 최소 버전을 확인한다.
- `.python-version`, `pyproject.toml`, `uv.lock`의 존재와 읽기 가능 여부를 확인한다.
- 고정 CPython 버전과 `.venv`가 잠금 환경에 맞는지 확인하고 손상·누락·불일치를 구분한다.
- FFmpeg와 ffprobe가 같은 배포본인지 확인하고 W-06~W-10이 요구하는 코덱과 필터를 검사한다.
- FFmpeg 탐색 우선순위는 환경 스크립트와 일치해야 하며 런처가 임의의 바이너리를 자동으로
  다운로드하지 않는다.
- 점검 결과는 기계적으로 타입이 있는 상태와 사용자 메시지로 분리해 테스트할 수 있어야 한다.
- Linux 명령행 경로와 공통 Python 앱 실행은 계속 동작해야 한다.

## 구성·복구·실행 요구사항

- 구성과 복구는 다음 명령 의미를 유지한다.

  ```powershell
  uv --managed-python sync --locked --no-dev
  ```

- 정상 실행은 다음 명령 의미를 유지한다.

  ```powershell
  uv --managed-python run --locked --no-sync -- movie-maker
  ```

- 런처 옵션과 앱 옵션은 첫 번째 `--`로 분리한다. 첫 `--` 뒤의 모든 값은 순서와 빈 문자열을
  포함한 원래 인자 단위로 Python 앱에 전달한다.
- 명령을 하나의 셸 문자열로 만들거나 `cmd.exe`를 경유하지 않는다. Windows 프로세스 API의
  구조화된 인자를 사용한다.
- 앱의 문서화된 `--project`는 공백과 유니코드 경로를 안전하게 전달하고 해당 프로젝트를 연다.
- `--online`을 제공한다면 앱 기능 모드일 뿐 환경 설치·업데이트를 뜻하지 않아야 한다.
- 환경 변경은 구성/복구에서만 수행한다. 일반 실행은 잠금 파일과 환경을 암묵적으로 바꾸지 않는다.
- 구성·복구 중 stdout/stderr와 종료 코드를 수집하고 진행 중임을 표시한다.
- 자식 앱이 정상적으로 시작됐는지와 시작 직후 실패했는지를 구분한다.

## 진단과 로그 요구사항

- 로그에는 단계, 시간, 실행 파일의 확인된 경로, 버전, 종료 코드와 제한된 프로세스 출력을
  기록한다.
- 비밀번호, 토큰, 전체 환경 변수와 불필요한 사용자 파일 경로를 기록하지 않는다.
- 사용자 화면에는 짧은 원인과 다음 행동을, 진단 보기에는 복사 가능한 세부사항을 제공한다.
- 로그 디렉터리는 `platformdirs` 또는 Windows의 적절한 사용자 데이터 위치와 일치시킨다.
- 로그 기록 실패가 앱 실행 자체를 막지 않으며, 대체 진단 방법을 제공한다.
- 오래된 로그의 보존 기간·용량 제한과 안전한 정리 경계를 둔다.

## 설치·업데이트·제거 요구사항

- 설치 산출물은 앱 파일, 런처와 필요한 메타데이터를 명확한 제품 디렉터리에 배치한다.
- Python 런타임, `.venv`, PySide6와 FFmpeg 실행 파일을 설치 파일에 암묵적으로 포함하지 않는다.
  배포 구성이 이 결정을 바꿔야 한다면 새 ADR과 라이선스 검토가 먼저 필요하다.
- 시작 메뉴와 선택적 바탕 화면 바로가기, `.mmrproj` 파일 연결을 설치 옵션으로 제공한다.
- 사용자 PATH 등록은 런처 디렉터리에 한해 선택적이다. 시스템 Python, `.venv`와 FFmpeg를 PATH에
  추가하지 않는다.
- 등록한 모든 항목은 소유권과 이전 값을 기록해 제거 시 정확히 되돌린다. 사용자가 나중에
  바꾼 값을 무조건 덮어쓰지 않는다.
- 사용자 프로젝트, 원본 미디어와 명시적으로 보존하기로 한 설정은 제거하지 않는다.
- 캐시·로그·자동 저장본 삭제는 별도 선택과 영향 설명을 제공한다.
- 업데이트는 사용자가 시작하고 버전·변경 내용·필요 공간을 보여 준다. 실패 시 기존 실행 가능한
  설치를 보존하거나 복구할 수 있어야 한다.
- 실행 중 파일 교체, 권한 부족, 재시작 필요와 다운그레이드/새 프로젝트 스키마 위험을 구분한다.
- 코드 서명은 인증서가 주어진 환경에서 재현 가능하게 적용할 수 있는 절차와 검증 단계를
  제공한다. 인증서가 없으면 서명됐다고 표시하거나 가짜 서명을 만들지 않는다.

## 런처 UI와 접근성

- 최소 UI는 환경 상태, 실행 모드, 구성/복구, 실행, 진단 로그와 유지관리 진입을 포함한다.
- 준비되지 않은 상태에서 실행 버튼을 누를 수 없다면 바로 옆에서 이유를 알 수 있어야 한다.
- 상태를 색상만으로 전달하지 않고 텍스트와 아이콘/패턴을 함께 사용한다.
- 키보드만으로 모든 행동에 접근할 수 있고 포커스 순서와 기본/취소 버튼이 Windows 관례를 따른다.
- 고배율과 고대비 모드에서 내용이 잘리거나 상태 구분이 사라지지 않는다.
- 긴 경로와 오류 세부사항은 레이아웃을 깨지 않고 선택·복사할 수 있다.

## 보안과 실패 안전성

- 다운로드, 설치, 환경 동기화와 업데이트처럼 네트워크나 파일을 바꾸는 행동은 사용자 동의 없이
  시작하지 않는다.
- 실행 파일 검색 결과를 사용하기 전에 실제 파일, 버전과 예상 프로그램인지 확인한다.
- 설치·제거 대상 경로를 절대 경로로 해석하고 제품 디렉터리 밖을 재귀적으로 지우지 않는다.
- 임시 다운로드와 설치 파일은 무결성을 검증하고 완료 전에 실행 가능한 최종 위치로 노출하지
  않는다.
- 실패한 설치·업데이트·제거는 가능한 한 이전 상태로 되돌리고 남은 항목과 수동 해결 방법을
  정확히 표시한다.
- 런처 종료, 취소와 예외 경로에서 프로세스 핸들, 파이프와 임시 파일을 정리한다.

## 필수 자동 검증

- uv 없음·구버전, 필수 파일 누락, Python 불일치, `.venv` 손상과 준비 상태 분류
- FFmpeg/ffprobe 불일치, 코덱·필터 누락과 탐색 우선순위
- 구성·복구·정상 실행 명령의 실행 파일과 정확한 argv
- 첫 `--`, 빈 인자, 공백·유니코드·따옴표·후행 백슬래시가 있는 인자 전달
- `--project`로 실제 앱 세션이 지정 프로젝트를 여는 흐름
- 구성·실행 취소, 제한 시간 초과, 비정상 종료와 자식 프로세스 정리
- 로그 성공·실패·용량 정리와 민감 정보 비기록
- 설치·업데이트·제거의 파일, 바로가기, 파일 연결과 선택적 PATH 왕복
- 사용자 변경 레지스트리 값과 프로젝트·원본·설정 보존
- 업데이트 실패 시 기존 실행 가능한 설치 보존
- 서명된 시험 산출물이 있는 경우 Windows 서명 검증, 없으면 명확한 미서명 상태
- 기존 PowerShell/Linux 환경 스크립트와 W-01~W-10 전체 회귀

실제 Windows 통합 검증은 공백과 한글이 있는 임시 설치 경로, 일반 사용자 권한과 실패 주입을
포함한다. 시스템 상태를 바꾸는 테스트는 격리된 범위에서 실행하고 항상 자신이 만든 등록만
정리한다.

## 문서와 완료 조건

- 런처 구현 언어·빌드 산출물, 상태 모델, 프로세스·인자, 로그와 설치 수명주기 계약을 새
  `DESIGN` 문서로 기록한다.
- 기존 ADR과 다른 런타임 번들 또는 배포 결정을 채택해야 한다면 새 ADR에 크기, 보안 업데이트와
  라이선스 영향을 기록한다.
- 사용자 README에 설치, 첫 실행, 환경 복구, 진단, 업데이트와 제거 절차를 실제 동작과 일치하게
  기록한다.
- 라이선스, 개인정보 처리와 서드파티 고지에 실제 배포 구성과 로그/네트워크 동작을 반영한다.
- 재현 가능한 Windows 설치 산출물과 릴리스 버전 정보를 만들고 새 설치·업데이트·제거 왕복을
  검증한다.
- 런처·설치 집중 테스트와 Python 전체 pytest, Ruff, strict mypy, 애플리케이션 점검이 통과한다.
- 처음 사용하는 사람이 터미널 없이 환경 상태를 이해하고 준비된 앱을 실행할 수 있다.

## 범위 제외

- Python 편집 로직을 런처 언어로 재작성
- FFmpeg 또는 제3자 바이너리의 무검토 자동 다운로드
- 자동 로그인, 클라우드 계정과 온라인 공유
- 사용자 동의 없는 백그라운드 업데이트
- 단일 실행 파일에 전체 Python 환경을 숨겨 넣는 방식
