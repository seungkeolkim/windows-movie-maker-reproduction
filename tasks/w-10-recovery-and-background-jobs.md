# W-10 자동 저장·복구·다시 연결·백그라운드 작업

## 작업 목표

장시간 편집에서 데이터 손실과 무거운 미디어로 인한 중단을 줄인다. 정상 프로젝트 파일을
보존하는 자동 저장과 비정상 종료 복구, 누락 원본의 검증된 다시 연결, 드래그 앤 드롭 가져오기,
실제 썸네일·파형·프록시 백그라운드 작업과 최근 프로젝트 상태를 구현한다.

## 저장 위치와 데이터 소유권

- 사용자 프로젝트는 계속 `.mmrproj` 단일 JSON 문서이며 자동 저장 때문에 프로젝트 옆에
  숨은 데이터베이스를 만들지 않는다.
- 자동 저장본, 캐시, 로그와 최근 목록은 `platformdirs`로 구한 사용자별 적절한 디렉터리에
  종류별로 분리한다.
- 자동 저장본은 정상 저장본과 다른 파일이며 정상 저장 행동이나 사용자의 명시적 선택 없이
  정상본을 덮어쓰지 않는다.
- 썸네일, 파형과 프록시는 재생성 가능한 캐시다. 프로젝트 JSON과 행동 이력에 바이너리 데이터,
  작업 진행 상태나 캐시 경로를 기록하지 않는다.
- 앱 전역 색인에 지속 저장소가 실제로 필요하다면 ADR-0004에 따라 SQLite를 우선 검토하고
  하나의 임베디드 엔진만 사용한다. 단순한 작은 JSON/파일 목록으로 충분하면 데이터베이스를
  추가하지 않는다.
- 캐시 키는 원본의 정규화된 경로만 믿지 않고 파일 정체성과 생성 설정을 포함한다. 원본이
  바뀌면 오래된 결과를 사용하지 않는다.

## 자동 저장 요구사항

- dirty 프로젝트를 문서화된 유휴 시간 또는 최대 간격에 따라 자동 저장한다.
- 저장 중 새 편집이 생기면 어느 프로젝트 세대가 저장됐는지 추적하고 최신 상태를 저장한
  것으로 잘못 표시하지 않는다.
- W-03과 같은 전체 직렬화·검증, flush/fsync와 원자적 교체 경계를 사용한다.
- 자동 저장 성공은 정상 저장 경로, 프로젝트명, dirty 기준과 행동 이력을 바꾸지 않는다.
- 정상 저장이 성공하면 그 시점보다 오래된 해당 프로젝트 자동 저장본을 안전하게 정리한다.
- 쓰기 실패와 디스크 부족은 편집을 막지 않되 지속적으로 숨기지 않고 상태와 해결 행동을
  표시한다.
- 앱 종료 중 진행 중인 자동 저장을 제한 시간 안에 완료하거나 취소하고 불완전한 임시 파일을
  정리한다.

## 복구 요구사항

- 시작 시 완전하게 기록되고 검증 가능한 자동 저장본만 후보로 찾는다.
- 정상 종료 표시와 자동 저장 세대를 사용해 실제 복구가 필요한 후보를 구분한다.
- 복구 화면은 프로젝트명, 정상 저장 시각, 자동 저장 시각과 이해 가능한 변경 요약을 보여 준다.
- 사용자는 자동 저장본 열기, 정상 저장본 열기 또는 나중에 결정을 선택할 수 있다.
- 자동 저장본을 열면 정상본을 그대로 보존하고 현재 세션을 dirty 상태로 시작한다. 사용자가
  저장하기 전에는 정상 경로를 덮어쓰지 않는다.
- 정상본을 열면 저장된 상태로 시작하고 선택한 오래된 복구본의 정리 여부를 명확히 한다.
- 나중에 결정은 어떤 파일도 바꾸지 않고 후보를 다음 시작에도 유지한다.
- 손상, 잘못된 참조와 지원하지 않는 새 스키마의 자동 저장본은 격리하고 현재 프로젝트를
  바꾸지 않는다.
- 지원하기로 한 이전 스키마는 원본과 다른 메모리/임시 사본에서 순차 마이그레이션한다.

## 누락 미디어 다시 연결

- 누락 항목은 마지막 경로, 종류, 길이, 화면 크기, 스트림 메타데이터와 영향을 받는 클립 수를
  표시한다.
- 사용자가 고른 후보를 ffprobe로 분석하고 저장된 종류·길이·크기·스트림 특성과 비교한다.
- 확실한 일치, 사용자가 확인해야 하는 차이와 명백한 불일치를 구분한다. 다른 파일을 조용히
  연결하지 않는다.
- 여러 누락 항목을 폴더에서 찾을 수 있더라도 각 대응의 근거와 충돌을 검증한다.
- 성공한 다시 연결은 원본 경로와 필요한 최신 메타데이터를 하나의 프로젝트 명령으로 바꾸고
  관련 모든 클립 ID와 편집점을 보존한다.
- 취소·분석 실패·불일치는 프로젝트, 이력과 dirty를 바꾸지 않는다.
- 다시 연결 전후에 후보 원본과 다른 모든 원본 파일을 수정하지 않는다.

## 백그라운드 작업 요구사항

- 미디어 가져오기와 프로젝트 열기 뒤 필요한 썸네일·파형·프록시를 우선순위가 있는 제한된
  작업자 큐에서 생성한다.
- UI는 전체와 항목별 대기, 진행, 준비, 취소와 실패 상태를 표시하며 편집을 계속할 수 있다.
- 같은 원본·설정 작업은 중복 실행하지 않고 유효한 캐시 결과를 재사용한다.
- 프로젝트 교체, 원본 변경, 프록시 해제와 앱 종료 시 관련 작업을 취소하고 오래된 콜백을
  폐기한다.
- 한 작업의 예외나 프로세스 실패가 큐와 다른 미디어 항목을 중단시키지 않는다.
- 파형은 실제 디코딩 샘플에서 시간 구간별 최소·최대 또는 동등한 결정적 요약을 만든다.
- 프록시는 문서화된 편집용 코덱·해상도·프레임률로 생성하고 원본과 시간 매핑 정보를 유지한다.
- 미리 보기만 준비된 프록시를 사용할 수 있다. 최종 출력은 항상 원본을 사용하며 원본이
  없으면 프록시만으로 성공한 출력처럼 처리하지 않는다.
- 캐시 파일은 고유 임시 파일에 만든 뒤 검증 성공 시 원자적으로 확정한다.
- 캐시 크기 제한, 오래된 항목 정리, 현재 사용 중 파일 보호와 수동 재생성 행동을 제공한다.

## 가져오기와 최근 프로젝트

- 탐색기 드래그 앤 드롭은 기존 파일 선택 가져오기와 같은 분석, 중복, 부분 성공과 원본 불변
  규칙을 사용한다.
- 파일과 폴더가 섞이면 지원하는 파일만 명시적으로 탐색하며 무제한 재귀나 숨은 대량 가져오기를
  피한다.
- 최근 프로젝트 목록은 성공적으로 저장하거나 연 프로젝트만 기록한다.
- 이동·삭제·접근 불가 항목을 구분하고 목록에서 제거할 수 있다. 목록 오류가 앱 시작이나 직접
  파일 열기를 막지 않는다.

## 동시성·오류·보안 요구사항

- 모든 파일 작업과 FFmpeg 프로세스는 UI 스레드를 장시간 막지 않는다.
- 프로세스는 셸 없이 argv로 실행하고 취소 시 terminate 후 제한 시간 내 kill 및 출력 회수를
  수행한다.
- 캐시 파일명에 신뢰하지 않는 원본 파일명을 직접 사용하지 않으며 캐시 루트 밖 경로를 쓰거나
  지우지 않는다.
- 정리 작업은 해석된 절대 경로가 해당 앱 캐시 루트 안인지 검증한 뒤 수행한다.
- 로그와 오류 UI는 원인 진단에 필요한 정보만 보존하고 불필요한 전체 사용자 경로 노출을 줄인다.

## 필수 자동 검증

- 자동 저장 원자성, 세대 경쟁, dirty·정상 경로·이력 불변과 정상 저장 후 정리
- 기록·동기화·교체·디스크 부족 실패에서 정상본과 이전 자동 저장본 보존
- 정상/비정상 종료 및 자동/정상/나중 선택의 복구 상태 전이
- 손상·새 스키마·이전 스키마 복구본의 거부 또는 마이그레이션
- 일치·부분 일치·불일치·취소 다시 연결과 클립/편집점 보존
- 드래그 앤 드롭과 파일 선택 가져오기의 결과 동등성
- 작업 큐 우선순위, 중복 제거, 취소, 프로젝트 세대 폐기와 실패 격리
- 실제 썸네일·파형·프록시 생성, 캐시 무효화와 임시 파일 정리
- 프록시 미리 보기 시간 일치와 최종 출력의 원본 사용 강제
- 캐시 용량 정리에서 활성 파일과 캐시 루트 밖 파일 보존
- 최근 프로젝트 추가·정리·손상 목록 복구
- 모든 원본과 정상 프로젝트 파일의 SHA-256, 크기와 수정 시간 불변
- W-01~W-09 및 전체 Qt UI 회귀

동시성 검증은 제어 가능한 시계, 실행기와 파일 시스템 실패 지점을 주입해 결과 순서를
결정적으로 재현한다. 실제 FFmpeg 검증은 서로 다른 해상도·프레임률·샘플률의 짧은 미디어로
수행한다.

## 문서와 완료 조건

- 자동 저장·복구, 재연결 식별, 작업 큐, 캐시 키·위치·수명주기와 프록시 계약을 새 `DESIGN`
  문서로 기록한다.
- 지속 저장소를 추가한다면 스키마, 마이그레이션, 백업, 잠금과 손상 복구를 함께 정의한다.
- README, 문서 지도, 화면·요소 표와 목업 상태를 실제 구현에 맞게 갱신한다.
- `V-ERROR-01`, `V-ERROR-02`, `V-ERROR-04`를 실제 파일과 서비스 검증으로 교체한다.
- 집중 테스트와 전체 pytest, Ruff, strict mypy, 애플리케이션 점검이 모두 통과한다.
- 강제 종료를 모사한 뒤 마지막 완전한 자동 저장본을 정상본 손상 없이 복구할 수 있다.

## 범위 제외

- 프록시를 사용한 최종 출력
- 원본 미디어의 자동 이동·삭제 또는 프로젝트 안 복제
- 클라우드 백업과 여러 장치 동기화
- 두 종류 이상의 임베디드 데이터베이스 엔진
- 온라인 미디어 검색과 공유
