# W-07 FFmpeg MP4 출력

## 작업 목표

고정 타이머와 가짜 결과 경로로 동작하는 출력 목업을 실제 FFmpeg 렌더링 작업으로 교체한다.
현재 프로젝트의 편집점, 화면, 영상·사진 프레임과 W-06 오디오 그래프를 하나의 H.264/AAC MP4
파일로 만들고 진행, 취소, 실패, 재시도를 안전하게 처리한다.

## 사용자 결과

- 시각 클립이 있는 프로젝트에서 출력 경로와 원본 유지, 720p 또는 1080p를 선택할 수 있다.
- 완성 파일은 MP4 컨테이너, H.264 영상과 AAC 오디오로 재생된다.
- 진행 중 상태와 대략적인 완료 비율·경과 시간·예상 남은 시간을 확인할 수 있다.
- 출력을 취소할 수 있고 취소 뒤 불완전한 파일이 최종 결과처럼 남지 않는다.
- 쓰기 권한, FFmpeg, 디스크, 원본 미디어와 인코딩 실패 이유 및 다음 행동을 확인할 수 있다.
- 실패 뒤 설정과 경로를 유지한 채 다시 시도할 수 있다.
- 완료 뒤 결과 파일 또는 포함 폴더를 열 수 있다.

## 출력 의미

- 렌더링은 시작 시점의 검증된 불변 `Project` 스냅샷을 사용한다. 진행 중 후속 편집이 허용되는
  경우에도 실행 중 그래프가 중간 상태로 바뀌지 않는다.
- 프로젝트 길이는 시각 스토리 라인의 끝이다. 시각 클립이 없으면 출력할 수 없다는 이유를
  표시한다.
- 컷, source in/out, 사진 길이, 재생 속도와 클립 경계는 W-04/W-05 시간 계산을 재사용한다.
- 정확한 경계에서는 뒤 클립이 시작하며 출력 프레임을 반복 덧셈으로 계산하지 않는다.
- 영상과 사진은 프로젝트 캔버스 비율을 유지한다. 다른 비율은 기본 맞춤과 중립 배경을
  사용하고 임의로 늘리지 않는다.
- `원본 유지`는 프로젝트에 저장된 기준 화면을 사용한다. 기준 미디어가 나중에 제거되거나
  순서가 바뀌어도 저장된 화면 크기를 다시 추론하지 않는다.
- 720p는 `1280×720`, 1080p는 `1920×1080`이다.
- 출력 프레임률은 MVP에서 하나의 문서화된 기본값 또는 기준 소스 정책을 사용한다. 가변
  프레임률 입력도 출력의 결정적인 프레임 경계로 변환한다.
- 오디오는 W-06 공통 그래프를 사용한다. 들을 수 있는 소스가 없더라도 출력 계약이 요구하는
  AAC 트랙을 결정적으로 생성하거나, 선택한 정책을 설계 문서와 UI에 명확히 기록한다.
- 미리 보기와 출력에서 컷 위치, 총 길이, 화면 배치와 음량의 의미가 같아야 한다.

## FFmpeg와 파일 안전 요구사항

- 렌더링 서비스는 Qt와 독립적으로 그래프 계획, argv 작성, 실행 상태와 오류를 타입으로
  제공한다.
- FFmpeg는 셸을 통하지 않고 구조화된 argv로 실행한다. 경로, 프로젝트명과 사용자 입력을
  명령 문자열로 이어 붙이지 않는다.
- 입력 스트림과 코덱을 명시하고 현재 환경 점검에서 요구하는 인코더·필터와 일치시킨다.
- 최종 대상과 같은 파일 시스템의 고유 임시 경로에 먼저 출력한다. 성공적으로 닫히고 검증된
  파일만 최종 대상으로 원자적으로 교체한다.
- 기존 대상 파일이 있을 때에는 사용자 확인 없이 덮어쓰지 않는다. 실패나 취소는 기존 정상
  파일을 보존한다.
- 취소, 실패와 앱 종료 뒤 임시 영상, FFmpeg 프로세스와 파이프를 정리한다.
- 원본 미디어는 모두 읽기 전용 입력이며 해시, 크기와 수정 시간이 바뀌지 않아야 한다.
- 완료 파일은 ffprobe로 컨테이너, 스트림, 길이, 크기와 디코딩 가능 여부를 검증한 뒤 성공으로
  표시한다.

## 진행과 동시성 요구사항

- FFmpeg 작업은 UI 스레드를 막지 않는다.
- `-progress` 등 기계 판독 가능한 출력을 사용해 프로젝트 전체 길이에 대한 단조 증가 진행률을
  계산한다. stderr의 지역화된 문장을 진행률 근거로 파싱하지 않는다.
- 진행률은 `0~100%`를 벗어나지 않고, 성공 검증이 끝나기 전에 완료로 표시하지 않는다.
- 동시에 하나의 프로젝트 출력만 허용한다. 중복 시작은 이유를 표시하고 새 프로세스를 만들지
  않는다.
- 취소 요청은 상태를 `취소 중`으로 바꾸고 terminate 후 제한 시간 안에 끝나지 않으면 kill한다.
- 창 종료나 프로젝트 교체 시 진행 중 작업을 어떻게 처리할지 확인하고 선택 결과에 따라
  안전하게 취소하거나 전환을 중단한다.
- 완료·실패 콜백은 작업 식별자가 현재 작업과 일치할 때만 UI에 반영한다.

## 오류 계약

최소한 다음 오류를 타입으로 구분하고 사용자 문장과 진단 세부사항을 분리한다.

- 출력 경로가 없거나 쓸 수 없음
- 대상 파일이 이미 존재함
- 디스크 공간 부족 또는 기록 중 I/O 실패
- FFmpeg 없음, 실행 불가, 필수 H.264/AAC 인코더나 필터 없음
- 원본 미디어 누락 또는 읽기 실패
- 지원하지 않는 입력 스트림이나 필터 조합
- FFmpeg 비정상 종료, 제한 시간 초과 또는 결과 검증 실패
- 사용자 취소와 앱 종료에 따른 취소

실패·취소는 프로젝트, 행동 이력, dirty 기준과 출력 설정을 변경하지 않는다. 진단 정보에는
필요한 종료 코드와 제한된 stderr를 보존하되 민감한 전체 환경이나 불필요한 경로를 노출하지
않는다.

## UI 요구사항

- `Ctrl+E`와 동영상 저장 행동은 같은 실제 설정 대화상자를 연다.
- 설정 화면은 프로젝트 길이, 기준 화면, 선택한 해상도와 결과 경로를 즉시 요약한다.
- 시각 클립이 없거나 누락 원본 때문에 출력할 수 없으면 비활성 이유와 해결 행동을 제공한다.
- 진행 패널은 실행, 취소 중, 취소됨, 실패, 완료를 구분한다.
- 진행 중 편집 명령과 중복 출력의 허용 여부를 일관되게 적용한다. 금지하는 행동은 비활성
  이유를 표시한다.
- 기존의 가짜 경로, 200ms 타이머와 실패 주입을 실제 서비스로 교체하되 테스트용 실행기
  주입 경계는 유지할 수 있다.

## 필수 자동 검증

- 원본 유지, 720p, 1080p의 캔버스와 비율 처리
- 영상·사진 순서, 트리밍, 분할, 사진 길이와 유리수 속도의 출력 시간
- W-06 원본음·음악 음량·음소거·배치와 출력 오디오 결과
- 공백·유니코드·긴 경로를 포함한 안전한 FFmpeg argv
- 진행률 단조성, 중복 시작 거부, 완료 전 100% 방지
- 취소·강제 종료·창 종료와 모든 임시 파일 정리
- 기존 대상이 있는 상태에서 성공·실패·취소 각각의 보존 규칙
- 누락 원본, FFmpeg 없음, 필터 없음, 쓰기 실패, 디스크 부족과 비정상 종료 분류
- 실패와 재시도에서 설정·프로젝트·이력·dirty 불변
- ffprobe 결과의 MP4/H.264/AAC, 해상도, 길이와 실제 디코딩 가능 여부
- 출력 전후 모든 원본 파일의 SHA-256, 크기와 수정 시간 불변
- W-01~W-06과 기존 Qt UI 전체 회귀

실제 통합 테스트는 수 초 길이의 영상·사진·오디오를 생성해 프레임 경계, 전체 길이와 대표
오디오 샘플을 허용 오차 안에서 비교한다. 로컬 FFmpeg가 없는 테스트 환경에서는 순수 계획기와
주입 실행기 검증을 유지하고, 실제 통합 검증의 생략 이유를 명시한다.
