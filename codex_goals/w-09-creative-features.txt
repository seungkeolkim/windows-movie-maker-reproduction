W-09 내레이션·텍스트·전환·시각 효과를 완전히 구현하라.
남아 있는 창작 기능 목업 값을 타입이 있는 불변 프로젝트 상태와 실제 미리 보기·출력 결과로 교체하라.

착수 전에 AGENTS.md와 tasks/w-09-creative-features.md 전체 및 연결된 W-06~W-08 설계 계약을 읽어라.
작업 트리가 깨끗하고 main이 origin/main과 동기화됐는지 확인한 뒤 main에서 feat/w09-creative-features 브랜치를 새로 생성하라.
같은 이름의 브랜치가 있거나 안전하게 생성할 수 없으면 기존 상태를 덮어쓰지 말고 원인을 확인하라.
모든 W-09 구현, 테스트와 문서 변경은 기능 브랜치에서만 수행하고 main에 직접 커밋하지 마라.

내레이션, 오디오 페이드·더킹, 텍스트, 화면 배치, 회전, 전환과 효과를 안정적인 프로젝트 값으로 표현하라.
프로젝트에는 사용자 의도와 프리셋 ID만 저장하고 FFmpeg 문자열, 장치 ID, 임시 파일과 위젯 상태를 저장하지 마라.
기존 프로젝트를 안전한 기본값으로 읽고 스키마 의미가 바뀌면 순차 마이그레이션과 새 버전 거부를 구현하라.
모든 지속 편집은 실제 ProjectCommand 하나로 적용하고 실패 시 프로젝트와 이력 위치를 유지하라.

외부 오디오를 내레이션 트랙에 추가하고 시작, source 구간, 음량과 음소거를 편집할 수 있게 하라.
주입 가능한 입력 장치 경계를 만들고 녹음의 시작·일시 정지·계속·완료·취소 상태를 UI 스레드 밖에서 처리하라.
녹음 취소·실패·창 종료 시 고유 임시 파일을 정리하고 완료 시 확인된 WAV 경로에 원자적으로 확정하라.
장치 없음, 권한 거부, 분리, 기록 실패와 디스크 부족을 구분하며 정상 파일과 프로젝트를 보존하라.
음악과 내레이션의 페이드 합이 사용 길이를 넘지 않게 검증하라.
클립 음량과 전체 믹서의 곱셈 순서를 고정하고 내레이션 구간의 더킹 attack/release를 문서화하라.
W-06 공통 오디오 그래프를 확장해 미리 듣기와 MP4 출력이 같은 음량·페이드·더킹 의미를 사용하게 하라.

제목, 캡션과 크레딧의 기본 시작 위치를 계약대로 계산하라.
내용, 절대 시작, 길이, 글꼴, 크기, 굵기, 색상, 정렬, 정규화 위치와 제한된 애니메이션을 저장하라.
빈 텍스트의 플레이스홀더는 편집 UI에만 표시하고 미리 보기와 출력에는 합성하지 마라.
안전 영역, 명암 대비, 글꼴 대체와 긴 크레딧 동작을 화면 비율과 해상도에 독립적으로 정의하라.

시각 클립별 맞춤·채움, 입력 회전 메타데이터 뒤의 사용자 회전, 밝기와 제한된 효과 프리셋을 구현하라.
전환은 인접한 두 시각 clip ID 경계에만 두고 양쪽 사용 구간을 침범하지 않게 길이를 제한하라.
이동·삭제·다중 편집으로 인접 관계가 사라지면 같은 명령에서 전환을 정리하고 undo로 복원하라.
임의 필터 문자열이나 실행 가능한 효과 코드를 프로젝트에서 받아 실행하지 마라.

W-05 미리 보기와 W-07 출력이 텍스트, 배치, 회전, 효과, 전환과 오디오를 하나의 공통 계획 의미로 처리하게 하라.
연속 탐색과 편집 직후 오래된 합성 결과를 폐기하고 누락 소스나 알 수 없는 프리셋을 명확한 오류로 표시하라.
실제 파형·프록시 생성과 캐시 수명주기는 W-10 범위로 남겨라.

녹음 상태와 파일 원자성, 오디오 그래프, 텍스트 저장·레이아웃, 시각 기하, 전환 인접성 및 미리 보기·출력 동등성 테스트를 추가하라.
작은 실제 미디어의 픽셀, 프레임 시간과 오디오 구간을 허용 오차 안에서 검증하고 W-01~W-08 전체 회귀를 유지하라.
pytest, Ruff, strict mypy, 애플리케이션 점검과 git diff --check를 모두 통과시켜라.
프로젝트 스키마, 명령, 오디오, 텍스트, 전환과 합성 계약을 새 DESIGN 문서에 기록하라.
README, 문서 지도, 기능·요소 표, 목업 연결 상태와 tasks의 완료 상태를 실제 결과에 맞게 갱신하라.

전문 색보정, 무제한 합성, 사용자 효과 플러그인, 안정화, 크로마키, 속도 램핑, 실제 파형·프록시와 온라인 자산은 이번 범위에 포함하지 마라.
