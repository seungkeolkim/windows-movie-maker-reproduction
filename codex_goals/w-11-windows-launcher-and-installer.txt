W-11 Windows 네이티브 런처와 설치 흐름을 완전히 구현하라.
터미널 없이 잠긴 uv 환경과 FFmpeg 상태를 진단·구성·복구하고 준비된 편집기를 실행할 수 있게 하라.

착수 전에 AGENTS.md와 tasks/w-11-windows-launcher-and-installer.md 전체 및 ADR-0001, 라이선스 정책과 현재 환경 스크립트를 읽어라.
작업 트리가 깨끗하고 main이 origin/main과 동기화됐는지 확인한 뒤 main에서 feat/w11-windows-launcher-installer 브랜치를 새로 생성하라.
같은 이름의 브랜치가 있거나 안전하게 생성할 수 없으면 기존 상태를 덮어쓰지 말고 원인을 확인하라.
모든 W-11 구현, 테스트와 문서 변경은 기능 브랜치에서만 수행하고 main에 직접 커밋하지 마라.

작은 네이티브 GUI 런처를 만들되 Python 편집·미디어 로직과 환경 해석 규칙을 런처에 복제하지 마라.
기존 PowerShell·Linux 명령행 경로와 공통 Python 애플리케이션 실행을 계속 지원하라.
런처 위치에서 앱 루트를 결정하고 uv 최소 버전, 필수 파일, 고정 Python, .venv와 잠금 일치 상태를 타입으로 분류하라.
FFmpeg와 ffprobe가 같은 배포본인지 확인하고 필요한 코덱·필터 및 환경 스크립트와 같은 탐색 우선순위를 검증하라.
런처가 임의 바이너리를 자동 다운로드하거나 일반 실행에서 잠금 환경을 바꾸지 않게 하라.

구성·복구는 uv --managed-python sync --locked --no-dev의 의미를 유지하라.
정상 실행은 uv --managed-python run --locked --no-sync -- movie-maker의 의미를 유지하라.
런처 옵션과 앱 옵션을 첫 번째 --로 분리하고 빈 값, 공백, 유니코드, 따옴표와 후행 백슬래시를 포함한 argv 단위를 보존하라.
명령을 셸 문자열로 만들거나 cmd.exe를 경유하지 말고 구조화된 Windows 프로세스 인자를 사용하라.
--project가 공백과 한글이 있는 프로젝트를 실제 앱 세션에서 열게 하라.
환경 변경은 사용자가 명시적으로 구성·복구를 승인한 경우에만 수행하라.
구성·실행의 stdout, stderr와 종료 코드를 수집하고 취소·창 종료에서 자식 프로세스와 핸들을 정리하라.
앱 정상 시작과 시작 직후 실패를 구분하라.

런처 UI는 준비되지 않음, 준비 중, 준비됨과 복구 필요 상태를 텍스트와 아이콘으로 보여라.
환경 상태, 구성·복구, 실행, 진단 로그와 유지관리 진입을 키보드로 모두 사용할 수 있게 하라.
비활성 실행 버튼 옆에 이유를 표시하고 긴 경로와 오류 세부사항을 선택·복사할 수 있게 하라.
고배율, 고대비와 Windows 포커스·기본 버튼 관례에서 내용과 상태 구분을 유지하라.

로그에는 단계, 시간, 확인된 실행 파일 경로, 버전, 종료 코드와 제한된 출력을 기록하라.
비밀번호, 토큰, 전체 환경 변수와 불필요한 사용자 경로를 기록하지 마라.
platformdirs에 로그를 두고 기록 실패가 실행을 막지 않게 하며 보존 기간·용량 제한과 안전한 정리를 구현하라.

재현 가능한 Windows 설치 산출물에 앱 파일, 런처와 메타데이터의 제품 디렉터리를 명확히 정의하라.
Python, .venv, PySide6와 FFmpeg를 암묵적으로 번들하지 말고 결정 변경 전 새 ADR과 라이선스 검토를 요구하라.
시작 메뉴, 선택적 바탕 화면 바로가기, .mmrproj 연결과 런처 디렉터리만의 선택적 PATH를 지원하라.
설치가 만든 파일·바로가기·레지스트리의 소유권과 이전 값을 기록하고 사용자 변경을 덮어쓰지 않으며 제거 시 정확히 복원하라.
사용자 프로젝트와 원본 미디어를 제거하지 말고 캐시·로그·자동 저장 삭제는 별도 선택과 영향 설명을 제공하라.
업데이트는 사용자 시작, 버전·변경 내용·공간 표시, 실패 시 기존 설치 보존과 복구를 지원하라.
인증서가 있을 때만 재현 가능한 코드 서명·검증 절차를 적용하고 없으면 미서명 상태를 명확히 표시하라.

환경 상태 분류, FFmpeg 탐색, 정확한 실행 argv, 프로젝트 열기, 취소·시간 초과·비정상 종료와 로그 안전성을 자동 검증하라.
공백과 한글이 있는 격리 경로에서 설치·업데이트·제거, 바로가기·파일 연결·선택적 PATH 왕복과 사용자 상태 보존을 테스트하라.
기존 환경 스크립트와 W-01~W-10 전체 회귀 및 pytest, Ruff, strict mypy, 애플리케이션 점검을 통과시켜라.
런처 언어·빌드, 상태 모델, 프로세스·argv, 로그와 설치 수명주기 계약을 새 DESIGN 문서에 기록하라.
README에 설치, 첫 실행, 복구, 진단, 업데이트와 제거 절차를 실제 동작과 일치하게 쓰고 정책·고지·tasks 상태를 갱신하라.

Python 편집 로직 재작성, 무검토 자동 다운로드, 자동 로그인·클라우드 공유, 사용자 동의 없는 업데이트와 전체 환경을 숨긴 단일 실행 파일은 이번 범위에 포함하지 마라.
