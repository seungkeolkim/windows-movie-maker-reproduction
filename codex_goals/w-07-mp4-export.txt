W-07 FFmpeg MP4 출력을 완전히 구현하라.
현재 고정 타이머와 가짜 결과 경로로 동작하는 출력 목업을 실제 비동기 렌더링 작업으로 교체하라.
현재 프로젝트의 편집 결과와 W-06 공통 오디오 그래프를 재사용해 재생 가능한 H.264/AAC MP4 파일을 생성하라.

착수 전에 AGENTS.md와 tasks/w-07-mp4-export.md 전체 및 그 문서가 지정한 승인 계약과 현재 구현을 읽어라.
기존 W-01부터 W-06까지의 시간 계산, 불변 프로젝트, 명령 이력, 저장 호환성, 미리 보기와 오디오 계약을 유지하라.
렌더링은 시작 시점의 검증된 Project 스냅샷을 사용하고 컷, 트리밍, 분할, 사진 길이, 재생 속도와 클립 경계를 정확히 반영하라.
원본 유지, 1280×720과 1920×1080 출력을 지원하고 화면 비율을 보존한 맞춤과 중립 배경 정책을 적용하라.
출력 프레임률과 경계 계산을 결정적으로 정의하고 미리 보기와 출력의 시간, 화면 배치와 음량 의미를 일치시켜라.

Qt와 독립적인 렌더 계획, 셸을 거치지 않는 FFmpeg argv, 실행 상태, 진행률과 타입이 있는 오류 경계를 구현하라.
같은 파일 시스템의 고유 임시 파일에 먼저 쓰고 ffprobe 검증까지 성공한 결과만 최종 경로로 원자적으로 교체하라.
사용자 확인 없이 기존 파일을 덮어쓰지 말고 성공, 실패와 취소 모두에서 기존 정상 파일과 모든 원본 미디어를 보존하라.
기계 판독 가능한 진행 출력을 사용해 단조 증가하는 진행률과 경과·예상 시간을 제공하고 검증 전에는 100%로 표시하지 마라.
중복 출력을 거부하고 취소, 제한 시간, 프로젝트 교체와 앱 종료에서 terminate 후 필요하면 kill하며 프로세스와 임시 파일을 정리하라.
UI 스레드를 막지 말고 시계, 파일 작업, 프로세스 실행기와 결과 검증기를 주입 가능하게 설계하라.

Ctrl+E와 동영상 저장 UI를 실제 설정, 진행, 취소, 실패, 재시도와 완료 결과 열기에 연결하고 관련 출력 목업만 제거하라.
경로, 디스크, 기존 대상, 누락 원본, FFmpeg, 인코더, 필터, I/O, 비정상 종료와 검증 실패를 구분해 사용자가 취할 다음 행동을 안내하라.
실패와 취소 및 재시도는 프로젝트, 행동 이력, dirty 기준과 출력 설정을 의도치 않게 변경하지 않아야 한다.
집중 단위 테스트, 주입 실행기 테스트, 실제 FFmpeg 통합 테스트, Qt 통합 테스트와 전체 회귀 테스트를 추가하라.
pytest, Ruff, strict mypy, 애플리케이션 점검과 git diff --check를 모두 통과시키고 새 DESIGN 문서, 문서 지도, README와 작업 상태를 실제 결과에 맞게 갱신하라.
MP4 외 형식, 하드웨어 인코더 자동 선택, 온라인 공유, 사용자 정의 코덱·필터, W-09 효과와 W-10 장시간 안정성 작업은 이번 범위에 포함하지 마라.
