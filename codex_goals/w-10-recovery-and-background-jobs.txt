W-10 자동 저장·복구·다시 연결·백그라운드 작업을 완전히 구현하라.
정상 프로젝트와 원본을 보존하면서 장시간 편집의 데이터 손실과 무거운 미디어 처리 지연을 줄여라.

착수 전에 AGENTS.md와 tasks/w-10-recovery-and-background-jobs.md 전체 및 연결된 저장·DB·미디어·출력 계약을 읽어라.
작업 트리가 깨끗하고 main이 origin/main과 동기화됐는지 확인한 뒤 main에서 feat/w10-recovery-background-jobs 브랜치를 새로 생성하라.
같은 이름의 브랜치가 있거나 안전하게 생성할 수 없으면 기존 상태를 덮어쓰지 말고 원인을 확인하라.
모든 W-10 구현, 테스트와 문서 변경은 기능 브랜치에서만 수행하고 main에 직접 커밋하지 마라.

사용자 프로젝트는 계속 단일 .mmrproj JSON 문서로 유지하라.
자동 저장본, 캐시, 로그와 최근 목록은 platformdirs의 사용자별 디렉터리에 종류별로 분리하라.
프로젝트 JSON과 행동 이력에는 바이너리 캐시, 작업 상태와 캐시 경로를 기록하지 마라.
앱 전역 색인이 실제로 필요할 때만 ADR-0004에 따라 SQLite 하나를 사용하고 작은 파일 목록으로 충분하면 DB를 추가하지 마라.
캐시 키에는 원본 파일 정체성과 생성 설정을 포함해 원본 변경 뒤 오래된 결과를 사용하지 않게 하라.

dirty 프로젝트를 유휴 시간과 최대 간격 정책에 따라 비동기로 자동 저장하라.
저장 세대를 추적해 저장 중 새 편집을 최신 상태로 오인하지 마라.
W-03의 전체 직렬화·검증, flush/fsync와 원자적 교체 경계를 재사용하라.
자동 저장 성공은 정상 저장 경로, 이름, dirty와 행동 이력을 바꾸지 않게 하라.
정상 저장 성공 뒤 그보다 오래된 해당 프로젝트 자동 저장본만 안전하게 정리하라.
쓰기 실패와 디스크 부족을 편집과 분리해 표시하고 종료 시 제한 시간 안에 완료·취소와 임시 파일 정리를 수행하라.

정상 종료 표시와 저장 세대로 완전하고 검증 가능한 복구 후보만 찾으라.
복구 화면에서 자동 저장본 열기, 정상본 열기와 나중에 결정을 지원하라.
자동 저장본은 정상본을 덮어쓰지 않고 dirty 세션으로 열며 정상본 선택은 저장된 상태로 열어라.
나중에 결정은 파일을 바꾸지 않고 후보를 유지하라.
손상·잘못된 참조·새 스키마 복구본은 격리하고 이전 스키마는 원본과 다른 사본에서 순차 마이그레이션하라.

누락 미디어 후보를 ffprobe로 분석해 종류, 길이, 크기와 스트림 특성을 비교하라.
확실한 일치, 확인이 필요한 차이와 불일치를 구분하고 다른 파일을 조용히 연결하지 마라.
성공한 다시 연결은 경로와 메타데이터를 프로젝트 명령 하나로 바꾸며 모든 clip ID와 편집점을 유지하라.
취소·분석 실패·불일치는 프로젝트, 이력, dirty와 모든 원본을 바꾸지 않게 하라.

썸네일·실제 파형·프록시를 우선순위와 동시성 제한이 있는 작업자 큐에서 생성하라.
중복 작업을 합치고 프로젝트 교체, 원본 변경, 프록시 해제와 종료에서 취소하며 오래된 콜백을 폐기하라.
한 작업 실패가 큐 전체를 중단하지 않게 하고 캐시는 고유 임시 파일에서 검증한 뒤 원자적으로 확정하라.
파형은 실제 샘플의 결정적 시간 요약을 만들고 프록시는 원본 시간 매핑을 유지하라.
미리 보기만 준비된 프록시를 사용하며 최종 출력은 항상 원본을 요구하라.
캐시 용량 제한, 활성 파일 보호, 안전한 루트 내부 정리와 수동 재생성을 제공하라.

탐색기 드래그 앤 드롭을 기존 파일 선택 가져오기와 같은 분석·중복·부분 성공 경계에 연결하라.
최근 프로젝트에는 성공적으로 저장하거나 연 항목만 기록하고 이동·삭제·접근 불가를 구분하라.
모든 프로세스는 셸 없이 argv로 실행하고 취소 시 terminate 후 제한 시간 내 kill과 출력 회수를 수행하라.
정리 대상의 해석된 절대 경로가 앱 캐시 루트 안인지 확인하고 신뢰하지 않는 파일명을 캐시 경로로 직접 사용하지 마라.

제어 가능한 시계·실행기·실패 지점을 주입해 자동 저장 경쟁, 복구 전이, 재연결, 큐 순서·취소·실패 격리를 결정적으로 테스트하라.
실제 미디어로 썸네일·파형·프록시, 캐시 무효화, 원본 출력 강제와 원본·정상본 불변을 검증하라.
W-01~W-09 전체 회귀와 pytest, Ruff, strict mypy, 애플리케이션 점검 및 git diff --check를 통과시켜라.
자동 저장·복구, 재연결, 작업 큐, 캐시 키·수명주기와 프록시 계약을 새 DESIGN 문서에 기록하라.
README, 문서 지도, 화면·요소 표, 목업 연결 상태와 tasks의 완료 상태를 실제 결과에 맞게 갱신하라.

프록시 최종 출력, 원본 자동 이동·삭제, 클라우드 백업·동기화, 복수 임베디드 DB와 온라인 미디어 검색·공유는 이번 범위에 포함하지 마라.
