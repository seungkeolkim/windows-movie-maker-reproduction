## 목적

이 문서는 프로그램이 사용자에게 제공할 기능을 1~2단계 깊이로 나열하고 각 기능의 범위,
사용자 결과, 관련 시나리오와 주요 의존성 또는 제약을 정의한다. 다음 단계의 화면 목록은 이
문서의 기능을 빠짐없이 제공하는 방향으로 작성한다.

이 문서는 구현 진행률을 관리하는 체크리스트가 아니다. 현재 구현 상태와 개발 순서는
[프로젝트 README](../../README.md)의 로드맵을 기준으로 확인한다. 기능을 코드 클래스,
FFmpeg 명령 또는 개별 버튼 수준으로 분해하는 일은 후속 설계 단계에서 수행한다.

## 범위 표기

| 표기 | 의미 |
| --- | --- |
| `MVP` | 짧은 영상을 가져와 편집·저장·출력하는 첫 사용 가능 버전에 반드시 필요 |
| `1.0` | Movie Maker다운 창작 경험, 안정성 및 배포 품질을 완성하기 위해 1.0 전에 제공 |
| `이후` | 1.0 완료 후 필요성과 비용을 다시 평가할 확장 후보 |

`명시적 제외`는 계획된 기능이 아니므로 `F-` 식별자를 부여하지 않고 문서 마지막에 별도로
기록한다. 기능의 구현 시점이 바뀌더라도 의미가 같으면 식별자를 유지한다.

### MVP 선행 구조: 편집 명령과 행동 이력

사용자에게 실행 취소·다시 실행 명령을 노출하는 시점은 1.0이지만, 나중에 편집 로직을 다시
작성하지 않도록 다음 구조는 MVP 구현 조건에 포함한다.

- 분할, 트리밍, 이동, 삭제, 길이 및 속도 변경처럼 프로젝트를 바꾸는 행동은 위젯이 상태를
  직접 수정하지 않고 명령 실행 경계를 통과한다.
- 각 명령은 실행에 필요한 입력과 실행 이전 또는 되돌리기에 필요한 정보를 보관한다.
- 같은 명령을 안전하게 되돌리고 다시 적용할 수 있는 계약을 둔다.
- 명령 실행 순서와 현재 위치를 세션 행동 이력에 기록한다.
- 새로운 편집을 수행했을 때 재실행 후보 이력을 정리하는 규칙을 둔다.
- UI와 목업 컨트롤러는 명령을 요청하고 결과 상태를 구독하며 이력 저장 방식을 직접 알지
  않는다.
- 프로젝트 저장 파일에는 현재 편집 결과를 기록한다. MVP에서는 실행 취소 이력을 앱 재시작
  이후까지 저장하지 않는다.

| `F-RUNTIME-05` | 1.0 | 실행 실패의 진단 정보와 로그 위치를 확인한다. | `SC-ERROR-01` | 사용자 안내와 상세 로그를 구분하고 민감한 경로 노출을 최소화한다. |
| `F-RUNTIME-06` | 1.0 | Windows에서 설치·업데이트·제거 흐름을 수행한다. | `SC-MVP-01`, `SC-ERROR-01` | 등록한 PATH, 바로가기와 파일 연결을 제거 시 되돌려야 한다. |

## 공통 제약

다음 제약은 특정 기능 하나가 아니라 전체 기능 인벤토리에 적용한다.

- **비파괴 편집:** 원본 미디어를 수정·이동·삭제하지 않고 프로젝트에는 참조와 편집 의도만
  저장한다.
- **명령 기반 변경:** MVP부터 프로젝트를 바꾸는 편집 행동을 되돌리고 재실행 가능한 명령
  경계로 처리하고 세션 행동 이력에 기록한다.
- **고정 편집 구조:** 1.0까지 순차적인 영상·사진 스토리 라인, 원본 오디오, 음악,
  내레이션과 텍스트의 제한된 구조를 사용한다.
- **미리 보기와 출력 일치:** 컷 위치, 표시 시간, 화면 배치, 효과와 음량의 의미가 같아야
  한다.
- **오프라인 핵심 기능:** 가져오기, 편집, 저장, 다시 열기와 출력에 계정이나 온라인 서비스를
  요구하지 않는다.
- **설명 가능한 실패:** 지원하지 않는 입력, 누락 미디어, 장치 문제와 출력 실패에서 원인과
  다음 행동을 함께 제공한다.
- **작업 상태 가시성:** 오래 걸리는 작업은 진행 상태와 취소 경로를 제공하고 취소 후 남는
  결과를 명확히 한다.
- **접근성:** 키보드 탐색, 보이는 포커스, 고대비와 텍스트 가독성을 목업 단계부터 검증한다.
- **독립 자산:** 원본 Movie Maker의 코드, 이름, 아이콘, 음원과 시각 자산을 복사하지 않는다.
- **라이선스:** 기본 제공 자산과 배포 구성은
  [POLICY-0001](../policies/policy-0001-licensing-and-output-rights.md)을 따른다.

## 명시적 제외

다음 항목은 1.0 기능으로 계획하지 않는다.

- 다중 카메라 편집
- 무제한 영상 트랙
- 노드 기반 합성
- 전문 색보정과 모션 그래픽
- 전문 오디오 워크스테이션 수준의 처리
- 클라우드 계정이나 인터넷 연결을 요구하는 핵심 기능
- 원본 Windows Movie Maker 바이너리, 코드, 이름, 아이콘, 음원과 상표 자산 재사용
- Microsoft `.mswmm` 및 `.wlmp` 프로젝트의 호환성 보장

## 중복으로 보이기 쉬운 기능의 경계

- `F-MEDIA-06`은 누락 사실과 영향을 안내하는 MVP 기능이고, `F-MEDIA-07`은 사용자가 새
  원본 경로를 지정하는 1.0 기능이다.
- `F-PREVIEW-03`은 시간 위치를 일반적으로 탐색하는 MVP 기능이고, `F-PREVIEW-05`는 실제
  프레임 경계를 기준으로 이동하는 1.0 기능이다.
- `F-EXPORT-03`부터 `F-EXPORT-05`는 짧은 출력에도 필요한 기본 피드백이고,
  `F-EXPORT-07`은 장시간 출력의 정확도와 복구 안정성을 강화하는 1.0 기능이다.
- `F-EXPERIENCE-03`은 모든 핵심 기능에 접근하는 기본 키보드 탐색이고,
  `F-EXPERIENCE-05`는 편집 효율을 높이는 명령 단축키 세트다.
- `F-TIMELINE-05`는 원본의 사용 구간을 줄이는 트리밍이고, `F-TIMELINE-16`은 클립의
  배치 길이를 유지한 채 참조 구간만 바꾸는 정밀 슬립 편집이다.

## 검토 결과

### R-01: 실행 취소·다시 실행 기반

사용자에게 보이는 `F-TIMELINE-11`과 `F-TIMELINE-12`는 1.0으로 유지한다. 명령 실행,
되돌리기, 재실행과 세션 행동 이력의 구조 및 배선은 MVP에서 먼저 마련한다.

### R-02: 사진 길이와 영상 속도의 별도 시나리오

`F-TIMELINE-06` 사진 표시 시간과 `F-TIMELINE-07` 영상 재생 속도는 MVP로 유지하되 별도
MVP 대표 시나리오는 추가하지 않는다. 기존 `SC-10-01`과 `SC-10-02` 연결 및 후속 상세 기능
검증으로 다룬다.

### R-03: 원본 비율과 해상도 유지

원본 영상 비율과 해상도를 유지하는 선택지를 MVP에 포함한다. 720p와 1080p 프리셋도 함께
제공한다. 서로 다른 원본이 섞인 프로젝트는 단일 출력 화면이 필요하므로 기준 원본과 여백
처리 규칙을 3~4단계의 상세 동작 명세에서 확정한다.

### R-04: 보관함 항목 제거

`F-MEDIA-04`를 MVP로 분류한다. 보관함에서 제거해도 원본 파일을 삭제하지 않으며,
타임라인에서 사용하는 항목은 영향을 먼저 알린다.
