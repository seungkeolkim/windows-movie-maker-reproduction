- 문서 번호: `PRODUCT-0001`
- 상태: 승인됨

## 목적

이 문서는 기능 인벤토리, 화면 구성, 상호작용 명세와 인터랙티브 목업을 평가할 공통 기준을
정한다. 구현할 수 있는 기능의 수보다 처음 사용하는 사람이 짧은 영상을 안전하게 완성하는
경험을 우선한다.

제품 전체 범위와 기술 로드맵은 [프로젝트 README](../../README.md)를 따른다. 이 문서는 그
내용을 UI 설계 관점에서 구체화하며, 기존 로드맵이나 아키텍처 결정을 대체하지 않는다.

## 주요 사용자

### U-PRIMARY: 처음 또는 가끔 영상을 만드는 사용자

가정용 영상, 여행 기록, 학교 과제와 짧은 기록물을 만들고 싶지만 전문 편집기의 트랙 구조와
용어에는 익숙하지 않은 사용자를 가장 먼저 고려한다.

필요한 경험은 다음과 같다.

- 가져오기부터 출력까지 다음 행동을 쉽게 찾을 수 있다.
- 분할, 트리밍과 순서 변경만 익혀도 결과물을 만들 수 있다.
- 실수해도 원본 파일이나 정상 프로젝트가 손상되지 않는다.
- 코덱과 렌더링 구조를 몰라도 일반적인 MP4를 출력할 수 있다.

### U-SECONDARY: 설명·내레이션 영상을 만드는 사용자

화면 녹화, 강의 또는 음성 설명 영상을 간단히 정리하려는 사용자를 1.0 경험의 두 번째
대상으로 둔다. 실수 구간 제거, 재생 속도, 내레이션, 배경 음악, 자막과 음량 균형이 주요
요구다.

### 주요 대상이 아닌 사용자

다음 요구를 중심으로 하는 전문 편집자는 1.0의 주요 대상이 아니다.

- 다중 카메라와 무제한 영상 트랙
- 정밀한 색보정과 모션 그래픽
- 노드 기반 합성과 전문 오디오 워크스테이션 수준의 처리
- 복잡한 플러그인 및 방송 제작 파이프라인

## 사용 환경

- 로컬 데스크톱 애플리케이션으로 사용한다.
- Windows의 화면 구성, 키보드 탐색, 고대비와 접근성 관례를 우선한다.
- Linux에서도 같은 핵심 작업 흐름이 동작하도록 설계하되 Windows 전용 관례에만 의존하지
  않는다.
- 마우스와 키보드를 기본 입력으로 사용하며 핵심 흐름에는 키보드 접근 경로를 제공한다.
- 핵심 편집 기능은 계정이나 지속적인 인터넷 연결을 요구하지 않는다.
- 사용자가 가진 로컬 영상, 사진과 오디오를 원본으로 사용한다.
- 초기 사용성 검토는 짧은 개인 프로젝트를 중심으로 하고, 장시간 프로젝트의 성능과
  안정성은 후속 품질 단계에서 검증한다.

목업은 최소한 일반적인 1920×1080 데스크톱과 제한된 1280×720 작업 영역에서 검토한다.
이는 지원 해상도 확정이 아니라 레이아웃이 특정 대형 화면에만 의존하지 않는지 확인하기
위한 초기 검토 기준이다. 고배율 디스플레이와 작은 화면의 최종 지원 기준은 실제 UI 구현과
함께 측정하여 확정한다.

## 제품 경험 원칙

### P-01: 완결된 작업 흐름

가져오기, 편집, 미리 보기, 프로젝트 저장과 동영상 출력이 하나의 이해 가능한 흐름으로
이어져야 한다. 특정 단계만 보여 주는 데모를 MVP 완료로 보지 않는다.

### P-02: 초보자도 예측 가능한 조작

버튼 이름, 아이콘, 배치와 동작 결과가 전문 용어를 모르는 사용자에게도 예측 가능해야 한다.
자주 쓰는 작업은 바로 보이게 하고 고급 설정은 점진적으로 드러낸다.

### P-03: 비파괴 편집과 복구 가능성

편집은 원본 미디어를 변경하지 않는다. 삭제나 덮어쓰기처럼 보이는 동작은 대상과 영향을
분명히 표시하며, 가능한 경우 실행 취소나 취소 경로를 제공한다.

### P-04: 상태의 투명성

현재 선택, 재생 위치, 프로젝트의 수정 및 저장 여부, 긴 작업의 진행 상태를 사용자가 알 수
있어야 한다. 사용할 수 없는 명령은 조용히 실패하지 않고 비활성화 상태나 이유를 제공한다.

### P-05: 즉각적이고 일관된 피드백

편집 조작은 화면과 미리 보기에 즉시 반영되어야 한다. 미리 보기, 설정 화면과 최종 출력은
서로 다른 결과를 암시하지 않아야 한다.

### P-06: 오류에서 다음 행동 제시

지원하지 않는 미디어, 누락된 파일과 출력 실패는 원인만 알리는 데 그치지 않고 사용자가
취할 수 있는 다음 행동을 함께 제시한다.

### P-07: 접근성

핵심 기능은 키보드로 탐색하고 실행할 수 있어야 한다. 고대비, 포커스 표시, 자막 가독성과
Windows 접근성 관례를 화면 설계 초기부터 고려한다.

### P-08: 독립적인 제품 정체성

원본 Movie Maker의 간결한 작업 흐름은 참고하되 코드, 이름, 아이콘, 음원, 시각 자산과 상표
표현을 복사하지 않는다. 목업도 독자적인 임시 자산을 사용한다.

## 대표 사용자 시나리오

### SC-MVP-01: 짧은 영상 완성

**대상:** U-PRIMARY

**목표:** 영상 두 개와 배경 음악 하나를 사용해 짧은 MP4를 만든다.

1. 새 프로젝트를 만든다.
2. 영상 두 개와 음악 파일을 가져온다.
3. 영상을 원하는 순서로 배치한다.
4. 각 영상의 불필요한 시작과 끝을 자른다.
5. 배경 음악의 위치와 음량을 조정한다.
6. 전체 결과를 미리 본다.
7. 프로젝트를 저장하고 원본 비율·해상도를 유지하거나 720p 또는 1080p MP4로 출력한다.

**성공 기준:** 처음 사용하는 사람이 외부 편집 도구 없이 흐름을 끝까지 수행하고, 현재
상태와 다음 행동을 각 단계에서 이해할 수 있다.

### SC-MVP-02: 중간의 실수 구간 제거

**대상:** U-PRIMARY

**목표:** 하나의 영상 중간에 있는 불필요한 구간을 제거한다.

1. 영상을 가져와 타임라인에 배치한다.
2. 미리 보기를 탐색해 제거할 구간의 시작점을 찾는다.
3. 시작점과 끝점에서 영상을 분할한다.
4. 가운데 클립을 삭제한다.
5. 남은 구간의 연결을 확인하고 출력한다.

**성공 기준:** 선택된 클립과 재생 위치가 명확하고, 분할과 삭제 결과를 예상할 수 있으며,
실수를 복구할 경로를 찾을 수 있다.

### SC-MVP-03: 저장 후 편집 재개

**대상:** U-PRIMARY

**목표:** 작업을 저장하고 애플리케이션을 다시 실행해 같은 위치에서 편집을 계속한다.

1. 편집 중인 프로젝트를 저장한다.
2. 프로젝트를 닫거나 애플리케이션을 종료한다.
3. 저장한 프로젝트를 다시 연다.
4. 미디어, 클립 순서, 편집점과 설정이 유지됐는지 확인한다.
5. 미디어를 찾을 수 없는 경우 문제와 가능한 다음 행동을 확인한다.

**성공 기준:** 저장 여부가 명확하고, 다시 연 프로젝트가 같은 편집 의도를 보존하며, 누락
미디어가 있어도 프로젝트 자체가 손상된 것처럼 보이지 않는다.

### SC-10-01: 여행 영상 꾸미기

**대상:** U-PRIMARY

**목표:** 영상과 사진에 음악, 캡션과 기본 전환을 더해 여행 영상을 만든다.

이 시나리오는 사진 표시 시간, 스토리보드와 타임라인 보기, 제목·캡션, 페이드 전환과 기본
화면 조정을 함께 검증한다.

### SC-10-02: 설명·내레이션 영상 만들기

**대상:** U-SECONDARY

**목표:** 화면 녹화 영상에서 실수를 제거하고 내레이션과 자막을 더한다.

이 시나리오는 재생 속도, 내레이션 트랙 또는 녹음, 오디오 파형, 페이드, 자동 더킹과 자막을
함께 검증한다.

### SC-ERROR-01: 작업 실패에서 회복

**대상:** 모든 사용자

**목표:** 읽을 수 없는 미디어, 누락 파일 또는 출력 실패가 발생했을 때 작업을 잃지 않고
다음 행동을 선택한다.

목업은 최소한 가져오기 실패, 누락 미디어, 출력 실패와 사용자가 취소한 상태를 재현한다.

## 범위 기준

### MVP

MVP는 다음 흐름을 실제로 완결할 수 있는 최소 범위다.

- 새 프로젝트, 저장, 다른 이름으로 저장과 다시 열기
- 영상, 오디오와 이미지 가져오기, 기본 정보·썸네일 표시 및 보관함에서 제거
- 미디어 보관함, 미리 보기와 기본 타임라인
- 하나의 순차적인 영상·사진 스토리 라인, 원본 오디오와 배경 음악
- 클립 추가, 이동, 삭제, 분할과 시작·끝 트리밍
- 사진 표시 시간과 영상 재생 속도 변경
- 재생, 일시 정지와 위치 탐색
- 원본 오디오와 배경 음악의 음량 및 음소거
- 누락되거나 읽을 수 없는 미디어 안내
- 원본 비율·해상도 유지 또는 720p 및 1080p MP4(H.264/AAC) 출력
- 저장 여부, 처리 진행, 취소, 완료와 이해 가능한 오류 피드백

MVP 목업은 위 기능의 실제 미디어 처리를 구현하지 않더라도 SC-MVP-01부터 SC-MVP-03과
SC-ERROR-01을 처음부터 끝까지 재현해야 한다.

사용자에게 보이는 실행 취소·다시 실행은 1.0 범위지만, 편집 로직은 MVP부터 명령 실행
경계와 세션 행동 이력 구조를 사용한다. 프로젝트 저장은 현재 결과 상태를 보관하며 세션의
실행 취소 이력을 다시 열기 이후까지 보존하는 기능은 MVP에 포함하지 않는다. 세부 결정은
[ADR-0002](../decisions/adr-0002-command-based-edit-history.md)를 따른다.

### 1.0

1.0은 MVP 흐름을 안정화하고 Movie Maker다운 창작 경험을 완성하는 범위다.

- 스토리보드와 확대 가능한 타임라인 보기
- 복제, 다중 선택, 리플 편집과 실행 취소·다시 실행
- 프레임 단위 탐색과 정밀한 편집 피드백
- 오디오 파형, 내레이션 트랙 또는 녹음, 페이드와 자동 더킹
- 제목, 캡션, 크레딧, 대표 전환과 시각 효과
- 회전, 화면 맞춤과 채움 및 기본 화면 조정
- 자동 저장, 비정상 종료 복구, 최근 프로젝트와 누락 파일 다시 연결
- 프록시 및 혼합 미디어 호환성, 장시간 작업 안정성
- 출력 품질·프레임률 설정과 견고한 진행률·취소·오류 복구
- 키보드 단축키, 접근성, 다국어화와 Windows 설치 흐름

### 이후 후보

- 카메라에서 직접 가져오기
- 마커, 정밀 슬립 편집과 속도 램핑
- 노이즈 감소와 간단한 EQ
- 고급 안정화, 색보정, 크로마키와 합성
- 테마 기반 자동 영화 만들기
- 사용자 효과 또는 전환 확장 시스템
- 추가 출력 코덱, 하드웨어 인코딩과 선택적 온라인 공유

### 1.0에서 제외

- 다중 카메라 편집과 무제한 영상 트랙
- 노드 기반 합성, 전문 색보정과 모션 그래픽
- 전문 오디오 워크스테이션 수준의 처리
- 핵심 기능에 필요한 클라우드 계정 또는 인터넷 연결
- 원본 Windows Movie Maker의 바이너리, 코드, 이름, 아이콘, 음원과 상표 자산 재사용
- Microsoft의 기존 `.mswmm` 또는 `.wlmp` 프로젝트 호환성 보장

## 범위 충돌 해소 기준

README의 기능 범위표와 단계별 로드맵에는 일부 기능의 시점이 다르게 기록되어 있다. 기능
인벤토리와 후속 설계 문서는 다음과 같이 승인된 기준을 적용한다.

| 항목 | 기존 기능 범위표 | 기존 단계별 로드맵 | 승인된 기준 |
| --- | --- | --- | --- |
| 제목·캡션·크레딧과 페이드 | MVP | 0.5 | 창작 기능이므로 0.5/1.0으로 두고 MVP에서는 제외 |
| 회전과 화면 맞춤·채움 | MVP | 0.5 | 0.5/1.0으로 두되 입력 방향 처리에 필수인지 기술 검증 후 재평가 |
| 프레임 단위 이동 | 1.0 | MVP | MVP에는 일반 탐색을 두고 프레임 정확도가 검증된 후 1.0 UI로 제공 |
| 출력 진행률·취소·오류 보고 | 1.0 | 품질 원칙상 모든 긴 작업에 필요 | MVP에도 기본 피드백과 취소를 포함하고 고급 복구는 1.0으로 확장 |

| 원본 비율·해상도 유지 | 완성 기능에만 언급 | 시점이 명시되지 않음 | MVP 출력 선택지에 포함 |

기준으로 갱신했다.

## 목업 평가 기준

각 대표 흐름의 목업은 다음 질문으로 검토한다.

- 사용자가 첫 행동과 다음 행동을 별도 설명 없이 찾을 수 있는가?
- 현재 프로젝트, 선택 항목, 재생 위치와 저장 여부를 알 수 있는가?
- 버튼의 이름과 활성 상태만으로 실행 결과를 예상할 수 있는가?
- 편집 결과와 원본 미디어가 구분되어 보이는가?
- 오류나 빈 상태에서도 막힌 이유와 다음 행동을 알 수 있는가?
- 작업을 취소하거나 실수에서 돌아갈 경로를 찾을 수 있는가?
- 일반 화면과 제한된 화면 크기에서 미리 보기와 타임라인을 사용할 수 있는가?
- 키보드 포커스와 고대비 상태에서도 주요 조작을 식별할 수 있는가?
