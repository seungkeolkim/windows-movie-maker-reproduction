# 기능 정의 및 UI 목업 작업 방식

- 문서 번호: `WORKFLOW-0001`
- 상태: 승인됨
- 관련 기준: [PRODUCT-0001: UI 설계 기준](../product/product-0001-ui-design-baseline.md)

## 목적

이 문서는 편집 기능을 실제 미디어 엔진에 연결하기 전에 제품 기능, 화면 구조와 사용자
동작을 정의하고 인터랙티브 목업으로 검증하는 작업 방식을 설명한다.

이 프로젝트는 전문 영상 편집기의 기능 수를 따라가기보다 처음 사용하는 사람도 영상을
빠르게 완성할 수 있는 경험을 목표로 한다. 따라서 구현 비용이 큰 재생·편집·렌더링 로직을
먼저 만들기보다, 기능을 찾고 이해하고 사용하는 흐름이 자연스러운지 목업에서 먼저
검증한다.

목업이 충분히 검토된 뒤에는 같은 화면과 동작 계약을 유지하면서 가짜 데이터를 프로젝트
모델, 미디어 분석기, 재생 엔진과 FFmpeg 출력 로직으로 차례로 교체한다.

## 기본 원칙

- 기능은 `MVP`, `1.0`, `이후 후보`, `명시적 제외` 중 하나로 분류한다.
- 기본 화면에는 현재 목표에 필요한 기능만 노출한다. 먼 미래의 기능을 빈 버튼으로 모두
  배치하지 않는다.
- 화면 구조와 사용자 흐름을 먼저 검증하되, 데이터 안전성과 프레임 정확도 같은 제품 원칙을
  훼손하는 상호작용은 목업에서도 허용하지 않는다.
- 정적인 그림이 아니라 대표 작업을 처음부터 끝까지 수행할 수 있는 인터랙티브 목업을
  만든다.
- 목업 단계의 상세 로직은 사용자 입력, 상태 변화, 피드백과 오류 상태를 정의한다. FFmpeg
  명령이나 저장 알고리즘 같은 실제 구현 세부사항은 이 단계에서 확정하지 않는다.
- 모든 화면과 동작은 상위 기능으로 추적할 수 있어야 한다. 목적이 연결되지 않는 UI 요소는
  제거하거나 보류한다.
- 전체 기능을 한 번에 설계한 뒤 목업을 만드는 대신 대표 사용자 흐름 단위로 설계, 구현,
  검토를 반복한다.

## 0단계: 기준 정의

### 목표

기능과 화면을 평가할 공통 기준을 정하고 범위 확장을 방지한다.

### 작업

- 주요 사용자와 사용 환경을 정의한다.
- 제품 원칙과 접근성 기준을 정리한다.
- 대표 사용 시나리오를 선정한다.
- MVP와 1.0의 경계를 확인한다.
- 이번 설계에서 다루지 않을 기능을 명시한다.

기준은 프로젝트의 [README](../../README.md)에 정의된 제품 목표와 로드맵을 우선 사용한다.
별도 문서에는 UI 설계와 검증에 필요한 내용만 요약하며, 기존 범위를 조용히 변경하지
않는다.

현재 프로젝트의 0단계 결과는
[PRODUCT-0001: UI 설계 기준](../product/product-0001-ui-design-baseline.md)에 기록한다.

### 완료 조건

- 각 기능의 포함 여부를 판단할 기준이 있다.
- 목업으로 검증할 대표 사용자 흐름이 정해져 있다.
- 제외하거나 연기한 기능의 이유가 기록되어 있다.

## 1단계: 기능 인벤토리

### 목표

프로그램이 제공할 기능을 1~2단계 깊이로 나열하고 우선순위를 부여한다.

### 작성 형식

```text
F-MEDIA. 미디어를 관리한다. [MVP]
  F-MEDIA-01. 영상·사진·오디오를 가져온다. [MVP]
  F-MEDIA-02. 미디어 정보를 확인한다. [MVP]
  F-MEDIA-03. 사용하지 않는 항목을 제거한다. [MVP]

F-EDIT. 클립을 편집한다. [MVP]
  F-EDIT-01. 클립을 배치하고 순서를 변경한다. [MVP]
  F-EDIT-02. 클립을 분할한다. [MVP]
  F-EDIT-03. 시작과 끝을 트리밍한다. [MVP]
```

기능 항목에는 다음 정보를 기록한다.

- 식별자와 이름
- 사용자가 얻는 결과
- 우선순위
- 관련 대표 시나리오
- 선행 기능 또는 주요 제약

기능 인벤토리는 구현 클래스나 라이브러리 목록이 아니다. 예를 들어 `FFmpeg 프로세스를
실행한다`가 아니라 `편집한 프로젝트를 MP4로 저장한다`처럼 사용자 관점에서 작성한다.

### 완료 조건

- 모든 기능에 우선순위가 있다.
- 각 MVP 기능이 하나 이상의 대표 시나리오와 연결된다.
- 중복 기능과 범위를 벗어난 기능이 분리되어 있다.

## 2단계: 화면 및 레이아웃 정의

### 목표

1단계의 기능을 발견하고 사용할 수 있도록 화면, 패널과 공통 UI 요소를 구성한다.

### 화면 유형

- 메인 윈도우
- 탭과 고정 또는 접이식 패널
- 별도 윈도우
- 모달 및 비모달 대화상자
- 팝오버와 컨텍스트 메뉴
- 공통 도구 모음과 상태 표시 영역
- 재사용 가능한 편집 컨트롤

빈 상태, 로딩, 진행 중, 오류와 완료는 불필요하게 별도 화면으로 만들지 않고 해당 화면의
상태로 정의한다.

각 화면에는 다음 정보를 기록한다.

- 화면 식별자와 이름
- 화면을 여는 진입점과 닫거나 벗어나는 방법
- 담당하는 기능 식별자
- 주요 영역과 배치 관계
- 크기 변경 시 동작과 최소 크기
- 키보드 포커스의 기본 이동 순서
- 다른 화면, 패널 또는 대화상자와의 관계

### 완료 조건

- 모든 MVP 기능에 접근할 화면 또는 명령 진입점이 있다.
- 각 UI 요소가 담당하는 기능을 역으로 추적할 수 있다.
- 같은 작업을 중복 제공하는 위치는 의도와 우선순위가 설명되어 있다.
- 일반 창 크기와 작은 창 크기에서 핵심 작업 영역이 유지된다.

## 3단계: 요소별 상세 기능 정의

### 목표

각 화면 요소에서 사용자가 수행할 수 있는 행동과 표시할 정보를 구체화한다.

예를 들어 타임라인에는 다음과 같은 상세 기능이 연결될 수 있다.

```text
S-TIMELINE: 타임라인
- I-TIMELINE-SELECT: 클립을 선택한다. → F-EDIT-01
- I-TIMELINE-REORDER: 클립 순서를 변경한다. → F-EDIT-01
- I-TIMELINE-SPLIT: 재생 헤드 위치에서 클립을 분할한다. → F-EDIT-02
- I-TIMELINE-TRIM: 클립의 시작과 끝을 조정한다. → F-EDIT-03
- I-TIMELINE-ZOOM: 시간축을 확대하거나 축소한다. → F-PREVIEW-02
```

각 상세 기능에는 다음 내용을 기록한다.

- 동작을 시작하는 입력과 사용할 수 있는 조건
- 선택, 포커스와 재생 헤드에 미치는 영향
- 화면에서 즉시 변하는 요소
- 실행 취소 및 다시 실행 대상 여부
- 키보드와 마우스에서 제공할 조작
- 다른 패널이나 명령 상태에 미치는 영향

### 완료 조건

- 화면에 표시된 모든 조작 요소에 동작 정의가 있다.
- 선택 상태와 비활성화 조건이 모순되지 않는다.
- 마우스가 없어도 핵심 흐름을 수행할 수 있는 조작 경로가 있다.

## 4단계: 목업 동작 명세

### 목표

목업이 재현해야 할 상태 변화와 실제 구현이 나중에 연결될 경계를 정의한다.

각 동작은 다음 형식으로 기술한다.

```text
동작: I-TIMELINE-SPLIT
진입 조건: 하나의 클립이 선택되고 재생 헤드가 클립 내부에 있다.
사용자 입력: 분할 버튼을 누르거나 지정된 키보드 단축키를 사용한다.
화면 결과: 선택한 클립이 재생 헤드를 기준으로 두 클립으로 표시된다.
상태 결과: 프로젝트가 수정됨 상태가 되고 실행 취소가 활성화된다.
제한: 재생 헤드가 클립 경계에 있으면 명령을 비활성화한다.
오류 피드백: 작업을 수행할 수 없는 이유를 상태 도움말로 알린다.
실제 연결점: TimelineService.split_clip(...)
```

최소한 다음 상태를 명세한다.

- 새 프로젝트와 미디어가 없는 상태
- 선택된 항목이 없는 상태와 하나 또는 여러 항목을 선택한 상태
- 수정되었지만 저장되지 않은 상태
- 미디어를 찾을 수 없거나 읽을 수 없는 상태
- 작업 대기, 진행, 취소, 실패와 완료 상태
- 실행 취소와 다시 실행 전후 상태
- 사용 가능한 기능이 없는 경우의 비활성화 상태

실제 연결점은 UI가 요구할 입력과 결과의 경계만 나타낸다. 함수 이름은 설계를 설명하기 위한
임시 이름일 수 있으며 실제 서비스 구조를 미리 고정하지 않는다.

### 완료 조건

- 목업에 필요한 정상, 빈 상태와 오류 상태가 정의되어 있다.
- 사용자 입력에 따른 상태 변화와 피드백이 설명되어 있다.
- 실제 로직으로 교체될 경계가 UI 코드와 구분되어 있다.

## 5단계: 인터랙티브 목업 생성

### 목표

고정된 샘플 데이터와 가짜 상태 변화를 사용해 대표 작업 흐름을 실행 가능한 형태로 만든다.

### 목업 범위

- 준비된 영상, 사진과 음악 항목을 미디어 보관함에 추가한다.
- 항목을 스토리보드 또는 타임라인에 배치한다.
- 선택, 이동, 분할, 트리밍과 삭제 결과를 메모리 상태에 반영한다.
- 선택 항목에 따라 속성 패널의 내용과 명령 활성 상태를 바꾼다.
- 실제 영상 대신 이미지, 색상 프레임 또는 시간 표시로 미리 보기를 흉내 낸다.
- 저장, 불러오기와 내보내기는 가짜 진행 상태와 결과를 표시한다.
- 개발자가 빈 상태, 누락 미디어와 처리 실패를 쉽게 재현할 수 있게 한다.

목업 UI는 사용자 동작을 위젯 내부에서 직접 처리하지 않는다. 화면은 사용자 의도를 신호나
명령으로 전달하고, 목업 컨트롤러 또는 저장소가 가짜 상태를 변경한다. 나중에는 이 경계를
유지하면서 목업 구현만 실제 프로젝트 및 미디어 서비스로 교체한다.

### 완료 조건

- 정해진 대표 시나리오를 중단 없이 처음부터 끝까지 수행할 수 있다.
- 정상 상태뿐 아니라 주요 빈 상태와 오류 상태를 확인할 수 있다.
- UI 위젯과 목업 상태 처리 책임이 분리되어 있다.
- 목업만 보고도 각 명령의 결과와 현재 프로젝트 상태를 이해할 수 있다.

## 6단계: 검토와 기준선 확정

### 목표

목업에서 발견한 불편을 수정하고 실제 로직을 연결할 안정적인 화면 및 동작 기준을 정한다.

### 검토 항목

- 처음 사용하는 사람이 다음 행동을 설명 없이 찾을 수 있는가?
- 대표 작업을 완료하기 위한 클릭과 화면 전환이 불필요하게 많지 않은가?
- 현재 선택, 재생 위치, 저장 여부와 작업 진행 상태를 알 수 있는가?
- 되돌릴 수 없는 것처럼 보이는 조작에 확인 또는 복구 경로가 있는가?
- 작은 창, 일반 창, 고배율 디스플레이에서 핵심 영역을 사용할 수 있는가?
- 키보드 탐색, 고대비와 텍스트 가독성이 Windows 관례에 맞는가?
- 오류 메시지가 문제와 다음 행동을 함께 알려 주는가?
- 미리 보기와 내보내기 설정이 서로 다른 결과를 암시하지 않는가?

검토 중 발견한 문제는 기능, 화면 또는 동작 명세에 다시 반영한 후 목업을 갱신한다. 한 차례
검토만으로 확정하지 않으며, 대표 시나리오가 완료 조건을 만족할 때 해당 흐름의 목업을
기준선으로 지정한다.

### 완료 조건

- 검토에서 발견된 중대한 사용성 문제가 해결되거나 보류 사유가 기록되어 있다.
- 승인된 화면과 동작 명세의 버전이 목업과 일치한다.
- 실제 로직을 연결할 순서와 각 연결 작업의 검증 기준이 정해져 있다.

## 대표 흐름별 반복 순서

2~5단계는 다음 흐름을 우선순위에 따라 하나씩 반복한다.

1. 미디어 가져오기 → 타임라인 배치
2. 탐색 → 분할 → 불필요한 구간 삭제
3. 클립 순서 변경 → 시작·끝 트리밍
4. 배경 음악 추가 → 음량 조절
5. 제목 또는 캡션 추가 → 미리 보기
6. 프로젝트 저장 → 닫기 → 다시 열기
7. 출력 설정 → 내보내기 → 완료 또는 실패 확인

앞선 흐름에서 확정한 공통 화면도 다음 흐름에서 문제가 발견되면 수정할 수 있다. 변경으로
인해 기존 흐름이 깨지지 않았는지 목업 시나리오를 다시 확인한다.

## 추적 식별자

문서, 목업과 이후 테스트에서 같은 대상을 일관되게 가리키기 위해 다음 접두사를 사용한다.

| 접두사 | 대상 | 예시 |
| --- | --- | --- |
| `SC-` | 대표 사용자 시나리오 | `SC-MVP-01` 짧은 영상 완성 |
| `F-` | 사용자 기능 | `F-EDIT-02` 클립 분할 |
| `S-` | 화면 또는 주요 화면 영역 | `S-TIMELINE` 타임라인 |
| `E-` | 화면 안의 조작 또는 표시 요소 | `E-PREVIEW-PLAY` 재생 버튼 |
| `I-` | 사용자 상호작용 | `I-TIMELINE-SPLIT` 분할 명령 |
| `M-` | 목업 상태 또는 결과 | `M-SPLIT-DISABLED` 분할 불가 상태 |

추적 관계는 다음과 같이 유지한다.

```text
기능 F-EDIT-02
    ↓
화면 S-TIMELINE
    ↓
요소 E-TIMELINE-SPLIT
    ↓
동작 I-TIMELINE-SPLIT
    ↓
목업 상태 M-SPLIT-SUCCESS / M-SPLIT-DISABLED
    ↓
실제 편집 서비스
    ↓
자동화 테스트
```

기능 식별자는 기능의 의미가 바뀌지 않는 한 유지한다. 삭제된 기능의 식별자를 다른 기능에
재사용하지 않는다.

## 실제 로직 연결 원칙

목업이 기준선을 통과하면 기능 흐름별로 실제 로직을 연결한다. 한 번에 전체 목업을 교체하지
않으며 다음 순서를 기본값으로 사용한다.

1. 가짜 미디어 정보 → ffprobe 기반 미디어 분석
2. 메모리의 목업 프로젝트 → 버전이 지정된 프로젝트 모델과 저장 파일
3. 가짜 미리 보기 → 실제 재생 및 탐색 엔진
4. 가짜 편집 상태 → 비파괴 타임라인 명령과 실행 취소 기록
5. 가짜 내보내기 → FFmpeg 렌더링, 진행률, 취소와 오류 처리

각 교체 작업은 기존 목업 시나리오를 계속 만족해야 한다. 실제 기술 제약으로 화면 계약을
바꿔야 한다면 코드에서 임의로 우회하지 않고 해당 기능, 화면 및 동작 명세를 먼저 갱신하고
변경 이유를 기록한다.

## 산출물 관리

단계별 상세 내용은 문서의 크기에 따라 하나의 설계 문서에서 시작한 뒤 다음 주제로 분리할
수 있다.

- 제품 기능 인벤토리
- 화면 목록과 레이아웃 명세
- 상호작용 및 상태 명세
- 목업 시나리오와 검토 기록

문서를 분리할 때는 [프로젝트 문서 안내](../README.md)의 카테고리와 파일명 규칙을 따르고
색인에 추가하며 기능 식별자를 유지한다. 구조 또는 기술 선택을 장기적으로 제약하는 결정은
일반 설계 문서에만 남기지 않고 순차 번호가 붙은 ADR로 기록한다.
