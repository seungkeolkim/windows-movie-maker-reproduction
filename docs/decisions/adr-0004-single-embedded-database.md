# ADR-0004: 파일 기반 경량 데이터베이스 단일화

- 상태: 승인됨
- 결정일: 2026-09-07
- 적용 대상: 애플리케이션 전역 색인, 캐시 메타데이터와 향후 로컬 영속 저장소
- 보완 결정:
  [ADR-0003: 프로젝트 코어 상태, 시간 단위와 저장 경계](adr-0003-project-core-state-and-storage.md)

## 배경

현재 프로젝트 문서는 버전이 붙은 단일 JSON 파일이고, 프로젝트 상태와 미디어 보관함에는
데이터베이스가 필요하지 않다. ADR-0003은 향후 앱 전역 색인에는 SQLite를 우선 검토하고
분석형 집계에는 DuckDB를 검토할 수 있다고 기록했다.

이 표현만으로는 서로 다른 기능이 생길 때마다 SQLite와 DuckDB를 각각 추가하는 설계도 허용할
수 있다. 두 파일 기반 데이터베이스를 함께 운영하면 의존성, 파일 위치, 스키마 마이그레이션,
백업, 잠금, 손상 복구와 진단 경로가 중복되어 제품 규모에 비해 관리 지점이 커진다.

## 결정

1. 현재 상태에서는 데이터베이스를 도입하지 않고 프로젝트별 버전 JSON과 세션 메모리 상태를
   유지한다.
2. 로컬 앱 데이터에 파일 기반 경량 데이터베이스가 실제로 필요해져도 한 애플리케이션 배포본은
   기본적으로 하나의 임베디드 데이터베이스 엔진만 사용한다.
3. 최근 프로젝트, 설정 보조 정보, 검색 색인과 캐시 메타데이터 같은 운영형 데이터에는 SQLite를
   기본 후보로 삼는다.
4. 분석형 집계가 측정 가능한 핵심 요구가 되고 SQLite로 충족하기 어렵다면 DuckDB를 대안으로
   평가한다. DuckDB를 채택할 때에는 기존 임베디드 저장소를 대체하거나 동일 엔진으로 통합하며,
   SQLite 옆에 두 번째 파일 DB로 병행 추가하지 않는다.
5. 기능별 구현 편의나 라이브러리 선호만으로 별도의 임베디드 DB를 추가하지 않는다. 선택한 한
   엔진이 파일 위치, 스키마 버전, 마이그레이션, 백업과 복구 정책을 함께 소유한다.
6. PostgreSQL 같은 별도 서버 데이터베이스는 다중 사용자 동시성, 중앙 동기화나 서버 질의처럼
   로컬 임베디드 DB와 본질적으로 다른 요구가 확인될 때만 검토한다. 서버 DB와 로컬 DB를 함께
   써야 한다면 데이터 소유권, 동기화 방향, 오프라인 동작과 장애 복구를 새 ADR로 승인한다.
7. 두 번째 데이터베이스 엔진이나 관련 런타임 의존성을 추가하려면 구현 전에 새 ADR에서 단일
   엔진으로 해결할 수 없는 근거, 운영 경계와 기존 저장소의 대체·마이그레이션 계획을 제시한다.

이 결정은 ADR-0003의 현재 프로젝트 JSON 저장 결정을 바꾸지 않는다. 향후 데이터베이스가
필요해질 때 선택과 운영 방식을 제한하는 보완 결정이다.

## 결과

### 장점

- 데이터베이스 의존성, 보안 업데이트와 배포 크기를 한 엔진으로 제한한다.
- 스키마 마이그레이션, 백업, 잠금과 손상 복구 경로가 중복되지 않는다.
- 운영형 저장과 분석형 저장을 나누기 전에 실제 요구와 측정 결과를 확인하게 한다.
- 외부 서버 DB가 필요한 경우 로컬 캐시와 권위 데이터의 경계를 명시적으로 검토한다.

### 비용과 제약

- 선택한 엔진에 덜 적합한 일부 질의는 애플리케이션 코드나 오프라인 변환으로 처리할 수 있다.
- 엔진을 바꿀 정도의 요구가 생기면 두 엔진을 병행하는 대신 명시적인 데이터 마이그레이션이
  필요하다.
- 서버 기능을 도입할 때에는 오프라인 우선 제품 범위와 운영 비용을 별도로 재검토해야 한다.

## 제외한 대안

### SQLite와 DuckDB 병행

운영형 데이터는 SQLite, 집계는 DuckDB에 나누면 각 엔진의 장점을 사용할 수 있지만 현재 제품
규모에서는 같은 로컬 데이터를 위한 스키마, 동기화와 복구 경계가 둘로 늘어난다. 별개의 서버
요구가 없는 한 관리 비용이 이점보다 커서 제외한다.

### 기능별 임베디드 데이터베이스

검색, 캐시 또는 분석 기능이 각자 저장소를 선택하면 초기 구현은 쉬울 수 있다. 그러나 사용자
장치에서는 여러 DB 파일과 수명주기를 하나의 애플리케이션이 책임져야 하므로 제외한다.

## 검증 기준

- 현재 의존성 목록과 소스에는 SQLite, DuckDB 또는 서버 DB 런타임이 없다.
- 데이터베이스를 도입하는 PR은 선택 엔진 하나와 해당 ADR을 명시한다.
- SQLite와 DuckDB를 동시에 의존하는 변경은 승인된 예외 ADR 없이는 허용하지 않는다.
- 저장소 문서는 프로젝트 JSON과 앱 전역 데이터베이스의 수명주기를 혼동하지 않는다.
