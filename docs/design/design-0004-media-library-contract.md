## 목적과 범위

W-02는 사용자가 선택한 여러 로컬 영상·사진·오디오 파일을 실제로 분석하고, 성공한 결과를
W-01의 `MediaReference`와 `CommandExecutor`를 통해 현재 프로젝트에 추가한다. 보관함은
분석된 이름, 종류, 길이, 화면 크기와 썸네일을 표시하고 파일별 실패 및 중복을 설명한다.

이번 작업은 프로젝트 파일 저장, 실제 타임라인 편집, 디코딩 재생, 오디오 믹싱과 MP4 출력을
구현하지 않는다. 드래그 앤 드롭, 프록시와 누락 미디어 다시 연결도 1.0 후속 범위로 유지한다.

## 모듈 경계

실제 미디어 코드는 `src/movie_maker/media/` 아래에 둔다.

| 모듈 | 책임 | 소유하지 않는 대상 |
| --- | --- | --- |
| `analysis.py` | ffprobe 실행, JSON 검증, 타입이 있는 분석 성공·실패 | 프로젝트 변경, Qt 위젯 |
| `thumbnail.py` | ffmpeg 한 프레임 추출과 메모리 PNG 결과 | 원본 파일, 프로젝트 문서 |
| `library.py` | 중복 판정, ID 발급, 코어 명령 실행, 부분 성공과 제거 | 파일 선택 대화상자, 타임라인 편집 |
| `__init__.py` | UI와 테스트에서 사용할 안정적인 W-02 이름 노출 | 구현 세부사항 |

Qt UI는 네이티브 다중 파일 선택 결과만 보관함 서비스에 전달한다. 분석기는 프로젝트를
변경하지 않고, 보관함 서비스만 성공한 분석 결과마다 `InsertMediaReference`를 실행한다.
항목 제거도 `RemoveMediaReference`를 통과한다.

## 지원 입력과 종류 판정

MVP 파일 선택 필터와 분석기가 인정하는 확장자는 다음과 같다. 확장자는 대소문자를 구분하지
않으며, 실제 스트림이 선언된 종류와 맞지 않으면 파일을 거부한다.

| 종류 | 확장자 | 필수 ffprobe 스트림 |
| --- | --- | --- |
| 영상 | `.3gp`, `.avi`, `.m2ts`, `.m4v`, `.mkv`, `.mov`, `.mp4`, `.mpeg`, `.mpg`, `.mts`, `.webm`, `.wmv` | 영상 스트림과 양의 길이 |
| 사진 | `.bmp`, `.jpeg`, `.jpg`, `.png`, `.tif`, `.tiff`, `.webp` | 양의 폭·높이의 영상 스트림 |
| 오디오 | `.aac`, `.flac`, `.m4a`, `.mp3`, `.ogg`, `.opus`, `.wav`, `.wma` | 오디오 스트림과 양의 길이 |

컨테이너 안에 영상과 오디오가 함께 있으면 파일 확장자가 정한 주 종류의 첫 유효 스트림을
대표 스트림으로 삼고, 이후 재생과 믹싱에 필요한 모든 영상·오디오 스트림 메타데이터는
보존한다. 앨범 표지 같은 보조 영상 스트림 때문에 오디오 파일을 영상으로 바꾸지 않는다.

## 원본 시간과 스트림 메타데이터

`MediaReference`는 W-01 필드에 다음 선택 메타데이터를 호환 가능하게 추가한다.

- `primary_stream_index`: 파일 종류를 대표하는 ffprobe 스트림 인덱스
- `streams`: 원본 스트림 순서와 무관하게 인덱스로 식별하는 불변 스트림 튜플
- 각 스트림의 `kind`, `codec_name`, 양의 유리수 `time_base`
- ffprobe가 제공한 정수 `start_pts`와 양의 `duration_ts`
- 영상 스트림의 선택적 평균 프레임률과 오디오 스트림의 선택적 샘플률

`time_base`는 한 원본 타임스탬프 단위가 몇 초인지 나타내는 양의 기약분수다. `start_pts`는
음수일 수 있고, ffprobe가 값을 제공하지 않으면 `null`로 남긴다. `duration_ts`가 있으면
`duration_ts × time_base`를 프로젝트 나노초 길이로 우선 변환한다. 없으면 스트림의 소수 초,
마지막으로 컨테이너의 소수 초 길이를 사용한다. 모든 소수는 `Decimal`로 파싱하며 `float`를
지속 상태에 넣지 않는다.

사진은 원본 시간 메타데이터를 보존할 수 있지만 `MediaReference.duration`은 계속 `null`이다.
영상·사진의 폭과 높이는 회전 메타데이터 적용 전 원본 픽셀 크기다.

W-01에서 만들어진 스트림 메타데이터 없는 `MediaReference`도 메모리 모델에서 계속 유효하다.
W-02로 실제 가져온 항목은 대표 스트림과 스트림 튜플을 반드시 채운다. W-03은 이 선택 필드를
프로젝트 JSON에 기록하고, 스트림이 없던 W-01 참조도 빈 기본값으로 읽는다. 상세 저장 계약은
[DESIGN-0005](design-0005-project-persistence-contract.md)를 따른다.

## ffprobe 실행과 오류 모델

분석기는 경로 문자열을 셸 명령으로 조립하지 않는다. `subprocess.run`에 실행 파일과 인자를
각각 전달하고 `shell=False`, 표준 입력 없음, stdout/stderr 캡처와 파일별 제한 시간을
사용한다. 따라서 공백, 한글·유니코드와 긴 경로를 별도 인용 없이 한 인자로 보존한다.

분석 결과는 예외 대신 다음 오류 코드를 포함한 타입이 있는 성공 또는 실패 값으로 반환한다.

| 오류 코드 | 의미 |
| --- | --- |
| `source_not_found` | 선택 경로가 일반 파일이 아니거나 가져오기 전에 사라짐 |
| `unsupported_type` | MVP 지원 확장자가 아님 |
| `ffprobe_not_found` | ffprobe 실행 파일을 시작할 수 없음 |
| `timeout` | 제한 시간 안에 분석이 끝나지 않음 |
| `process_failed` | ffprobe가 비정상 종료함 |
| `invalid_json` | stdout이 UTF-8 JSON이 아니거나 최상위 구조가 잘못됨 |
| `invalid_media` | 필요한 스트림, 길이, 크기 또는 시간 기준이 없음 |
| `command_rejected` | 분석 후 프로젝트 명령 경계가 추가를 거부함 |
| `internal_error` | 주입된 서비스가 계약 밖 오류를 내거나 잘못된 결과를 반환함 |

stderr 세부 정보는 진단에 사용할 수 있도록 길이를 제한해 보존하되, 사용자 화면에는 파일명과
해결 가능한 짧은 이유를 표시한다. 한 파일의 예외나 잘못된 데이터는 다음 파일 분석을 막지
않는다.

## 중복과 부분 성공

중복 키는 절대 경로를 정규화하고 Windows에서는 대소문자를 접은 값이다. 현재 프로젝트에
이미 있는 경로와 같은 선택 묶음 안에서 앞서 성공한 경로를 모두 비교한다. 중복 파일은 다시
분석하거나 새 ID를 만들지 않고 기존 항목 이름과 함께 별도 건너뜀 결과로 보고한다.

각 파일은 `분석 → MediaReference 변환 → InsertMediaReference 실행 → 썸네일 시도` 순서로
처리한다. 분석이나 명령이 실패한 항목은 프로젝트에 들어가지 않는다. 다른 항목에서 이미
성공한 명령은 유지하므로 혼합 입력은 부분 성공한다. 가져오기 결과는 성공, 실패, 중복과
썸네일 경고를 각각 파일별 튜플로 보존한다.

파일 선택이 취소되어 경로가 없으면 프로젝트와 행동 이력, dirty 상태와 기존 보관함을 바꾸지
않고 취소 상태만 안내한다.

## 썸네일

영상과 사진은 분석이 성공한 뒤 ffmpeg가 대표 영상 스트림의 한 프레임을 PNG로 stdout에
출력한다. 영상은 시작부의 대표 프레임, 사진은 첫 프레임을 사용하고 최대 보관함 크기에 맞게
비율을 유지해 축소한다. 출력 파일이나 임시 원본 사본은 만들지 않는다.

PNG 바이트와 썸네일 오류는 세션 메모리 캐시에만 둔다. 썸네일 실패는 해당 미디어 가져오기를
되돌리지 않으며 기본 종류 아이콘을 표시하고 파일별 경고를 남긴다. 항목을 성공적으로 제거할
때 관련 캐시도 함께 버린다.

## 항목 제거와 원본 안전

보관함 서비스는 타임라인의 어느 클립이 참조하는 항목을 제거하지 않는다. UI는 관련 클립
수를 먼저 보여 주고 사용자가 클립을 제거한 뒤 다시 시도하도록 안내한다. 코어의
`RemoveMediaReference`도 같은 불변식을 최종 방어한다.

사용하지 않는 항목만 명령으로 프로젝트에서 제거하고 메모리 썸네일 캐시를 비운다. 가져오기,
분석, 썸네일과 제거 경로 어디에도 원본 파일의 쓰기·복사·이동·삭제 API를 두지 않는다.

## 데이터베이스 판단

W-02에도 데이터베이스를 추가하지 않는다. 프로젝트 미디어 참조는 W-01의 불변 튜플에 있고,
썸네일은 실패해도 재생성할 수 있는 세션 캐시다. 검색용 앱 전역 색인, 공유 상태 또는 분석형
집계 요구가 없어 SQLite나 DuckDB의 수명주기·마이그레이션 비용을 정당화하지 못한다. 후속
범위에서 DB가 필요해져도 [ADR-0004](../decisions/adr-0004-single-embedded-database.md)에 따라
파일 기반 경량 엔진은 하나만 선택한다.

## 자동 검증

- 영상·사진·오디오 ffprobe JSON과 `MediaReference` 변환
- `time_base`, `start_pts`, `duration_ts`, 프레임률과 샘플률 보존
- 정상·미지원·손상 파일 혼합 입력의 부분 성공
- ffprobe 없음, 비정상 종료, 잘못된 JSON과 타임아웃의 타입이 있는 실패
- 공백·유니코드·긴 경로가 셸 없이 단일 subprocess 인자로 전달됨
- 기존 프로젝트 및 같은 선택 묶음의 중복 가져오기 방지
- 썸네일 성공과 실패 격리, 메모리 캐시 정리
- 원본 파일 내용과 메타데이터 무변경
- 사용 중 항목 제거 거부와 사용하지 않는 항목 제거
- 파일 선택 취소 및 UI 성공·부분 실패·중복 결과 표시
- 기존 W-01 코어와 UI 목업 회귀

W-02는 새 검증 35개를 추가했고 W-01 및 기존 UI 회귀를 합한 전체 89개 테스트가 통과했다.
실제 FFmpeg 9.0.1 환경에서도 1초 H.264/AAC MP4, PNG와 PCM WAV를 함께 가져오고, 손상 MOV와
미지원 TXT가 각각 격리되는지 확인했다. 가져오기 전후 다섯 파일의 SHA-256, 크기와 수정 시간이
모두 같았다.

분석과 썸네일 생성은 현재 UI 스레드에서 파일별로 순차 실행한다. 느린 저장장치나 큰 묶음의
진행·취소와 백그라운드 실행은 W-10 범위다. 실제 지원 코덱은 사용자가 제공한 FFmpeg 빌드에
따른다. W-03은 프로젝트 재실행 뒤 미디어 참조를 복원하며 재생성 가능한 썸네일 바이트는
프로젝트 파일에 저장하지 않는다.
