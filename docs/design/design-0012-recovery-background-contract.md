# 자동 저장·복구·다시 연결과 백그라운드 작업 계약

- 문서 ID: `DESIGN-0012`
- 상태: 승인됨
- 연결 작업: `W-10`
- 최종 갱신: 2026-09-15

## 책임과 저장 위치

사용자 프로젝트는 계속 `schema_version`을 가진 단일 `.mmrproj` UTF-8 JSON 문서다. 자동
저장, 최근 목록과 재생성 가능한 미디어 캐시는 프로젝트 밖의 `platformdirs` 사용자 디렉터리에
각각 둔다. 데이터, 캐시, 로그, 자동 저장, 격리 저장소를 분리하며 별도 데이터베이스는 쓰지
않는다. 프로젝트 JSON과 명령 이력에는 캐시 경로, 바이너리와 작업 상태를 기록하지 않는다.

`ApplicationPaths`가 경로를 한곳에서 구성한다. 최근 목록은 작고 원자적으로 교체되는 JSON이며
성공적으로 저장하거나 연 프로젝트만 기록한다. 항목은 사용 시점에 `available`, `missing`,
`inaccessible`로 다시 판정하며 손상된 목록은 앱 시작과 직접 열기를 막지 않는다.

## 자동 저장과 복구

`AutosaveCoordinator`는 dirty 편집의 불변 `Project` 스냅샷을 유휴 5초 또는 최초 변경 후
최대 120초에 한 번의 작업자로 보낸다. 편집마다 증가하는 generation과 완료 generation을
따로 추적하므로 저장 중 생긴 새 편집은 저장된 것으로 간주하지 않는다. 자동 저장은 정상
경로, 프로젝트명, dirty 기준과 명령 이력을 바꾸지 않는다.

자동 저장 파일은 메타데이터와 W-03 전체 프로젝트 문서를 함께 담는다. 고유 임시 파일에 쓰고
flush/fsync한 뒤 `os.replace`하며 완전한 파일만 후보가 된다. 정상 저장 성공 시 그 시점까지의
generation만 지우고, 이미 실행 중이던 오래된 자동 저장이 늦게 완료돼도 다시 정리한다.
쓰기 실패는 편집과 분리해 상태에 남기며 이전 완전본과 정상본을 보존한다.

세션 저널은 시작 직후 unclean으로 기록되고 정상 종료 뒤에만 clean으로 바뀐다. 시작 시 이전
세션이 unclean이거나 사용자가 결정을 미룬 완전한 자동 저장만 후보로 찾는다. 복구 화면은
프로젝트명, 정상·자동 저장 시각, generation과 변경 요약을 보여 준다.

- 자동 저장본: 정상본을 덮어쓰지 않고 dirty 세션으로 연다.
- 정상 저장본: 검증된 정상본을 clean 세션으로 열고 사용자가 거절한 해당 복구본을 정리한다.
- 나중에 결정: 프로젝트 파일을 바꾸지 않고 deferred 표시만 원자적으로 남긴다.

손상됐거나 지원하지 않는 새 스키마의 자동 저장은 프로젝트를 바꾸지 않고 전용 격리
디렉터리로 이동한다. 지원하는 이전 스키마는 읽어 들인 사본에서 순차 변환하며 원본 파일을
수정하지 않는다.

## 다시 연결

`MediaRelinker`는 사용자가 고른 파일을 ffprobe로 분석해 저장된 종류, 길이, 화면 크기와 스트림
구성을 비교한다. 종류 또는 허용 오차를 넘는 길이는 mismatch, 크기·스트림 등의 차이는 명시적
확인이 필요한 confirm, 차이가 없으면 exact다. mismatch, 취소와 분석 실패는 프로젝트와 이력을
바꾸지 않는다.

승인된 교체는 `ReplaceMediaReference` 명령 하나로 경로와 분석 메타데이터를 바꾼다. asset ID,
모든 clip ID와 편집점은 그대로이며 undo로 이전 참조를 복원한다. 폴더 검사는 한 단계의 동일
파일명 후보를 항목별로 분석하고 한 파일을 둘 이상의 항목에 배정하지 않는다. 확인이 필요한
후보는 자동 연결하지 않는다.

## 작업 큐와 캐시

썸네일, 실제 오디오 파형과 프록시는 동시성 2의 우선순위 큐에서 실행한다. 화면에 필요한
썸네일·파형이 프록시보다 우선하며 동일 cache key의 대기·실행 작업은 합친다. 프로젝트 교체,
원본 다시 연결, 프록시 해제와 종료는 관련 작업을 취소한다. generation이 지난 결과 콜백은
버리고 한 작업의 실패는 다른 작업자를 중단하지 않는다.

모든 FFmpeg/ffprobe는 셸 없이 argv로 실행한다. 취소와 시간 초과에서는 terminate 후 제한 시간
안에 끝나지 않으면 kill하고 stdout/stderr를 회수한다. 캐시 생성은 고유 partial 파일 또는
메모리 결과를 검증한 뒤 원자적으로 게시하며 종료 시 partial을 정리한다.

cache key는 원본의 해석된 절대 경로, 크기, 수정 시각, device/inode와 생성 설정의 SHA-256이다.
원본 이름은 캐시 파일명으로 쓰지 않는다. 원본이 변하면 이전 key는 재사용되지 않는다. 캐시
정리는 기본 5 GiB 한도에서 오래 사용하지 않은 항목부터 삭제하며, 미리 보기가 사용할 준비된
프록시는 pin해 보호한다. 모든 삭제 대상은 해석된 경로가 캐시 루트 내부인지 먼저 검증한다.
미디어 속성의 `캐시 다시 생성`은 선택 항목의 소유 캐시만 지우고 필요한 작업을 다시 예약한다.

파형은 FFmpeg가 디코딩한 8 kHz mono float 샘플을 고정 bucket의 min/max JSON으로 요약한다.
프록시는 960×540, 30 fps, H.264/AAC MP4이며 원본 길이를 허용 오차 안에서 검증한다. 준비된
프록시는 `preview_project`에서만 경로를 치환한다. 저장과 최종 MP4 출력은 항상 원본 경로를
가진 지속 프로젝트를 사용하며 원본이 없으면 프록시만으로 출력을 성공시키지 않는다.

## UI 및 검증 경계

파일 선택과 탐색기 드롭은 같은 분석·중복·부분 성공 경계로 들어간다. 폴더 드롭은 숨은 파일과
하위 폴더를 건너뛰고 한 단계, 최대 200개만 명시적으로 수집한다. 실제 분석과 캐시 생성은 UI
스레드 밖에서 실행되며 전체·항목별 대기, 생성 중, 준비, 취소와 실패 상태를 표시한다.

결정적 시계와 수동 실행기로 자동 저장 경쟁을 검증하고, 큐 우선순위·중복·취소·실패 격리와
캐시 루트 보호를 단위 테스트한다. 실제 FFmpeg 통합 테스트는 썸네일, 파형과 프록시 생성,
시간·해상도 검증, 캐시 재사용 및 원본의 SHA-256·크기·수정 시각 불변을 확인한다.
