## 목적과 범위

W-07은 불변 `Project` 스냅샷의 시각 트랙과 W-06 공통 오디오 그래프를 실제 재생 가능한
MP4로 만든다. 컨테이너는 MP4, 영상은 H.264 `libx264`, 오디오는 AAC이며 출력 프레임률은
30fps CFR로 고정한다. 원본 유지, 1280×720, 1920×1080 크기를 지원한다.

다른 컨테이너, 하드웨어 인코더 자동 선택, 온라인 업로드, 사용자 필터, W-09 효과와 W-10의
장시간 복구 정책은 범위가 아니다.

## 모듈 경계

| 모듈 | 책임 |
| --- | --- |
| `exporting/plan.py` | Qt 독립 스냅샷, 크기·시간과 셸 없는 FFmpeg argv |

| `exporting/verifier.py` | ffprobe 메타데이터와 전체 디코딩 검증 |
| `exporting/coordinator.py` | 단일 백그라운드 작업과 오래된 콜백 억제 |
| `ui/exporting.py` | 작업자 콜백을 Qt 소유 스레드 신호로 전달 |

출력 서비스는 Qt, 목업 상태나 가변 UI 값을 import하지 않는다. 시계, 파일 작업, 프로세스
실행기와 검증기는 테스트에서 주입할 수 있다.

## 렌더 계획과 미디어 의미

출력 시작 시점의 `Project`를 그대로 보관한다. 이후 편집은 새 불변 프로젝트를 만들 수 있지만
실행 중 계획을 바꾸지 않는다. 출력은 프로젝트 파일, 명령 이력, dirty 기준과 원본 파일을
변경하지 않는다.

시각 클립은 저장된 순서와 반열린 경계를 사용한다. 영상은 source in/out을 먼저 자르고
`PlaybackRate`로 PTS를 변환한다. 사진은 저장된 클립 길이만큼 반복한다. 모든 클립은 30fps로
정규화하고 프로젝트 화면에 비율을 유지한 채 맞춘 뒤 `0x20242b` 여백을 더해 이어 붙인다.
마지막 프레임 수는 프로젝트 길이에 속하는 CFR 타임스탬프 수를 올림한 값이다.

원본 유지는 저장된 `Canvas` 크기를 그대로 사용한다. 짝수 크기는 호환성이 높은 `yuv420p`,
홀수 크기는 크기를 바꾸지 않기 위해 `yuv444p`를 사용한다. 720p와 1080p는 각각 1280×720,
1920×1080과 `yuv420p`다. 오디오는 W-06의 48kHz 스테레오 그래프를 입력 오프셋만 조정해
그대로 사용하며 소리가 없어도 결정적인 무음 AAC 트랙을 만든다.

## 파일 안전과 검증

대상 폴더에 `.<이름>.<고유값>.partial.mp4`를 만든다. 대상이 이미 있으면 사용자의 명시적 교체
확인 전에는 작업을 시작하지 않는다. FFmpeg 성공 뒤에도 임시 파일을 바로 게시하지 않고
ffprobe로 MP4/H.264/AAC, 요청 크기·길이와 정확한 프레임 수를 확인하고 FFmpeg로 영상과
오디오를 끝까지 디코딩한다. 파일을 flush/fsync한 뒤 같은 파일 시스템에서 최종 이름으로
원자적으로 게시한다.

교체 확인이 없는 새 대상은 하드 링크 생성으로 경쟁 상태의 덮어쓰기를 막는다. 확인된 교체는
`os.replace`를 사용한다. 실패와 취소는 임시 파일을 정리하고 기존 정상 결과를 보존한다.

## 진행, 동시성과 취소

FFmpeg의 `-progress pipe:1` 키·값을 사용하며 지역화된 stderr 문장을 진행률로 해석하지 않는다.
인코딩 진행률은 단조 증가하고 검증 전에는 최대 99%다. 검증과 게시가 끝난 뒤에만 완료 단계와
100%를 보낸다. 경과 시간은 주입 가능한 단조 시계로 계산하고 진행률이 유효할 때 남은 시간을
추정한다.

동시에 하나의 출력만 허용한다. 중복 요청은 새 프로세스를 만들지 않는다. 취소는 상태를 먼저
취소 중으로 바꾸고 프로세스에 terminate를 보낸 뒤 0.5초 안에 끝나지 않으면 kill한다. 프로젝트
교체와 창 종료는 사용자의 확인 뒤 같은 취소·정리 완료를 기다린다. 작업 ID가 다르거나 서비스
종료 뒤 도착한 콜백은 UI에 반영하지 않는다.

## 오류 계약

출력 경로 없음·쓰기 불가·기존 대상, 디스크 부족, 원본 누락, FFmpeg·ffprobe 없음, H.264/AAC
인코더나 필터 없음, 미지원 입력, I/O, 프로세스 비정상 종료, 제한 시간, 결과 검증과 내부 오류를
서로 다른 `ExportErrorCode`로 전달한다. 사용자 문장에는 다음 행동을 포함하고, 진단 상세는
최대 2,000자로 제한해 별도 상태에 보관하며 기본 화면에 그대로 노출하지 않는다.

실패와 취소는 선택한 경로·프리셋을 유지해 재시도할 수 있게 한다. 프로젝트와 행동 이력,
dirty 기준은 성공 여부와 무관하게 유지한다.

FFmpeg 환경 점검, Linux 스크립트 구문 검사와 `git diff --check`가 통과했다.
