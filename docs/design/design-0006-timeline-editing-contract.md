## 목적과 범위

W-04는 목업 상태를 직접 바꾸던 MVP 타임라인 동작을 UI와 무관한 실제 `ProjectCommand`로
교체한다. 미디어 추가, 시각 클립 이동, 단일 클립 삭제, 영상·오디오 분할, 시작·끝 트리밍,
사진 표시 시간과 영상 재생 속도 변경을 W-01의 `CommandExecutor` 한 세션에 연결한다.

실제 영상·오디오 디코딩, 미리 보기 프레임 동기화, 믹싱, MP4 출력, 다중 선택 편집, 복제,
텍스트·전환·효과와 고급 리플은 이번 범위가 아니다. 해당 화면은 기존 목업 표시를 유지한다.
데이터베이스와 새 프로젝트 스키마 버전도 추가하지 않는다.

## 소유권과 모듈 경계

| 경계 | 책임 | 소유하지 않는 대상 |
| --- | --- | --- |
| `project/model.py` | 지속 상태의 시간·참조·트랙 불변식 | UI 입력, ID 생성 |
| `timeline/editing.py` | 경계 스냅, 결과 길이, 실제 편집 명령과 최소 역명령 | Qt, 파일 I/O, 디코딩 |
| `project/commands.py` | 명령 커밋, 세션 이력, 실패 원자성 | 편집별 시간 정책 |
| `media/library.py` | 한 `CommandExecutor`를 미디어와 타임라인 서비스에 공유 | 선택·재생 위치 |
| `ui/mock_controller.py` | 밀리초·float 입력 변환, ID 주입, 화면 상태 투영과 오류 안내 | 지속 상태 계산 |

UI 선택, 재생 위치, 미리 보기 음소거, 타임라인 확대와 패널 상태는 프로젝트 명령이나 JSON,
행동 이력에 넣지 않는다. 편집 명령은 파일 시스템과 원본 미디어를 열지 않는다.

## 지속 상태 불변식

1. 시간은 모두 정수 나노초 `ProjectTime`이고 재생 속도는 양의 기약분수 `PlaybackRate`다.
2. 영상·오디오 클립은 `0 <= source_in < source_out <= media.duration`을 만족한다.
3. 영상·오디오 클립 길이는 `source span / playback rate`를 나노초로 가장 가까운 정수에
   반올림한 값이다. 정확히 절반이면 0에서 먼 쪽, 즉 양수 시간에서는 뒤 틱을 선택한다.
4. 사진 클립은 `source_in = 0`, `source_out = null`, 재생 속도 `1/1`이고 양의 표시 길이만
   가진다.
5. 시각 트랙은 프로젝트 0초부터 빈 구간 없이 이어지며 순서나 길이가 바뀔 때 앞에서부터
   각 `timeline_start`를 다시 계산한다.
6. 음악·내레이션·텍스트 트랙은 프로젝트 절대 시작 위치를 유지한다. 시각 리플 때문에 자동
   이동하지 않으며 서로 겹칠 수 있다.
7. 프로젝트 길이는 마지막 시각 클립 끝이다. 시각 클립이 없으면 0이다.
8. 클립 ID는 프로젝트 전체에서 유일하다. 이동, 트리밍, 속도·길이 변경과 분할 앞쪽 결과는
   기존 ID를 유지하며 분할 뒤쪽만 주입된 새 ID를 사용한다.

기존 스키마 1의 필드만으로 이 불변식을 표현할 수 있으므로 W-03 JSON 형식은 바꾸지 않는다.
역직렬화에서도 같은 불변식을 검증하며 잘못된 과거 문서를 조용히 보정하지 않는다.

## 미디어 경계 스냅

클립의 source in/out은 컨테이너 시작을 0으로 본 상대 시간이다. 원본 `time_base`, `start_pts`,
`duration_ts`, 평균 프레임률과 샘플률은 W-02 값 그대로 보존한다. `start_pts`는 디코더가 원본
PTS로 복귀할 때 사용할 메타데이터이며 상대 편집점을 변경하지 않는다.

내부 편집점은 다음 우선순위로 가장 가까운 경계에 맞춘다.

1. 대표 영상 스트림에 평균 프레임률이 있으면 `frame_index / frame_rate` 격자를 사용한다.
2. 대표 오디오 스트림에 샘플률이 있으면 `sample_index / sample_rate` 격자를 사용한다.
3. 대표 스트림은 있으나 위 정보가 없으면 `tick_index * time_base` 격자를 사용한다.
4. 분석 전 프로젝트처럼 스트림 메타데이터가 없으면 입력 나노초를 그대로 사용한다.

가장 가까운 인덱스는 매 요청마다 미디어 원점과 유리수 비율에서 직접 계산한다. 이전 경계에
간격을 반복해 더하지 않으므로 24000/1001, 30000/1001과 60000/1001fps의 긴 구간에도 누적
오차가 없다. 앞뒤 경계까지 거리가 같으면 뒤 경계를 선택한다. 미디어 0과 정확한 원본 끝은
항상 유효한 단말 경계이며, 내부 스냅 결과는 그 범위 안으로 제한한다.

평균 프레임률은 VFR 파일의 개별 PTS 목록이 아니므로 W-04에서 가능한 결정적 근사다. W-05가
실제 디코딩 타임스탬프를 제공하면 동일 명령 인터페이스 앞의 경계 공급기를 실제 PTS 격자로
교체하고 별도 호환 결정을 기록한다.

## 편집 명령

### 미디어 클립 추가

- 영상과 사진은 `visual`, 일반 오디오는 `music`, 사용자가 내레이션을 명시한 오디오는
  `narration` 트랙에 추가한다.
- 시각 클립은 끝에 붙이고, 음악·내레이션은 명시적 시작 위치가 없으면 해당 트랙의 가장 늦은
  끝에 붙인다.
- 영상·오디오는 원본 전체 구간, 사진은 5초 기본 표시 길이를 사용한다.
- 첫 시각 클립이고 화면 기준이 없으면 해당 미디어의 폭·높이와 ID를 canvas에 고정한다.
- ID는 UI 어댑터가 주입하며 명령은 중복 ID와 종류가 맞지 않는 명시적 트랙을 거부한다.

### 시각 클립 이동과 삭제

- 이동은 한 시각 클립의 순서만 바꾸고 모든 ID, 원본 참조, source in/out과 속도를 유지한다.
- 대상 인덱스가 범위 밖이거나 현재 인덱스와 같으면 이유가 있는 `CommandRejected`를 반환한다.
- 단일 삭제는 원본 미디어 참조를 유지한다. 시각 삭제 뒤 남은 시각 클립만 리플한다.
- 삭제 뒤 UI는 선택을 해제하고 재생 위치를 새 프로젝트 길이 안으로 제한한다.
- 다중 선택 삭제는 W-08 범위이며 W-04 실제 명령 경계에서는 거부한다.

### 분할

- 영상과 오디오 클립만 내부 재생 위치에서 분할한다. 사진과 텍스트는 거부한다.
- 요청한 프로젝트 위치를 현재 재생 속도로 source 위치에 변환한 뒤 미디어 경계에 스냅한다.
- 양쪽 결과의 재생 길이가 각각 250ms 이상이어야 한다.
- 앞쪽은 기존 ID와 label을 유지하고 뒤쪽은 주입된 새 ID와 ` (뒤)` label을 사용한다.
- 뒤쪽 시작은 앞쪽 실제 결과 끝이며 시각 트랙의 이후 클립은 전체 재계산한다.
- 성공 후 UI는 뒤쪽을 선택하고 재생 위치를 그 시작으로 옮긴다.

### 트리밍과 속성 적용

- 시작 트리밍은 source in, 끝 트리밍은 source out을 스냅한 경계로 바꾼다.
- 영상·오디오 트리밍 결과의 재생 길이는 최소 500ms다.
- 사진 표시 시간은 UI-MOCK-BASELINE-1에 따라 1~30초 범위다.
- 영상 속도는 현재 UI가 제공하는 `1/2`, `1/1`, `3/2`, `2/1`을 사용하고 오디오와 사진에는
  적용하지 않는다.
- 속도 변경은 source in/out을 바꾸지 않고 결과 길이만 유리수로 다시 계산한다.
- 속성 패널에서 source in, source out, 사진 길이와 영상 속도를 함께 적용해도 하나의
  `UpdateClipTiming` 명령과 이력 항목으로 커밋한다.
- 음량, 음소거, 맞춤·채움과 효과는 W-06 또는 W-09 전까지 목업 값으로 남으며 W-04 지속
  명령과 JSON에 섞지 않는다.

## 명령 원자성과 역명령

각 명령은 현재 불변 `Project`를 읽고 새 `Project`와 영향을 받은 트랙 구간 또는 클립의 이전
값만 가진 역명령을 반환한다. 전체 프로젝트, 미디어 바이트, 썸네일과 UI 상태를 복사해 이력에
넣지 않는다.

`CommandExecutor`는 명령 적용과 결과 검증이 모두 성공한 뒤 프로젝트, 이력과 위치를 한 번에
교체한다. execute, undo 또는 redo 중 예외·거부·계약 위반이 발생하면 세 값은 그대로다. UI는
성공한 뒤에만 투영 상태와 dirty를 갱신한다. undo 뒤 새 명령은 기존 redo 분기를 제거한다.

컨트롤러는 마지막 성공 저장본의 `Project` 값을 보관하고 현재 값과 비교해 dirty를 계산한다.
저장은 이력을 유지한 채 저장 기준값만 갱신한다. 새 프로젝트와 열기는 새 실행기, 빈 이력과
새 저장 기준값으로 시작한다. 실패한 저장·열기는 이 셋을 바꾸지 않는다.

## UI 연결과 피드백

- 기존 화면 구조, 위젯 이름과 `UI-MOCK-BASELINE-1` 배치를 유지한다.
- 추가·이동·삭제·분할·트리밍·속성 적용은 공유 실행기의 실제 명령을 호출한다.
- `Ctrl+B`, `Delete`, `Ctrl+Z`, `Ctrl+Y`와 기존 메뉴·도구 모음도 같은 경계를 호출한다.
- 성공 후 프로젝트를 화면 모델로 다시 투영하고 선택, 재생 위치, 속성 패널, 전체 길이와
  제목의 `*`를 한 번에 갱신한다.
- 실패는 선택과 입력 조건, 유효 범위 또는 다음 행동을 포함한 한국어 상태 메시지를 표시한다.
  프로젝트, 이력, dirty와 선택은 바꾸지 않는다.
- 테스트는 클립 ID 생성기, 미디어 분석기, 파일 선택기와 저장 경계를 주입할 수 있다.

## W-03 연동과 원본 안전

저장은 현재 실행기의 `Project`를 기존 `ProjectFileStore`에 전달한다. 저장 직전 UI 목업
스냅샷에서 프로젝트를 재구성하지 않는다. 같은 파일을 열면 나노초 시간, 유리수 속도, 트랙
순서, ID와 원본 참조가 동일한 `Project`로 복원된다.

편집 명령과 직렬화기는 원본 경로를 값으로만 다루며 원본 파일을 복사·수정·이동·삭제하거나
mtime을 갱신하지 않는다. SQLite, DuckDB, PostgreSQL 등 데이터베이스를 추가하지 않는다.

## 필수 자동 검증

- 영상·사진·음악·명시적 내레이션의 고정 트랙 추가와 시각 연속 시작 위치
- 시각 이동·삭제의 안정적인 ID·원본 참조와 빈 구간 없는 리플
- 영상·오디오 내부 분할, 사진·경계·최소 길이 미만 분할 거부
- 시작·끝 트리밍, 원본 범위 제한, 사진 길이와 유리수 영상 속도
- 24000/1001, 30000/1001, 60000/1001fps 장기 경계와 오디오 샘플 경계
- 음수·0 길이·원본 초과·잘못된 참조와 트랙 종류 거부
- 모든 명령의 execute → undo → redo 값 왕복, 순서·레이블과 redo 분기 제거
- 명령·undo·redo 실패의 프로젝트·이력·dirty 무변경
- 속성 한 번 적용의 이력 한 항목과 보조 트랙 절대 위치 유지
- W-03 JSON 왕복과 저장 전후 원본 해시·크기·수정 시간 불변
- W-01~W-03 및 기존 Qt UI 전체 회귀
