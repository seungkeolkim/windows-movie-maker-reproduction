# DESIGN-0011: 창작 기능과 공통 합성 계약

## 상태

승인 및 W-09 구현 완료. 이 문서는 내레이션 녹음, 오디오 페이드·더킹·전체 믹서,
텍스트, 화면 배치·회전·효과, 인접 전환과 미리 보기/출력 공통 합성 의미를 고정한다.
W-06~W-08의 오디오 그래프, MP4 게시와 명령 이력 계약을 확장하며 대체하지 않는다.

## 지속 프로젝트 값과 호환성

W-09는 `schema_version` 1에 선택 필드를 추가한다. 기존 필드의 의미를 바꾸지 않으므로 버전을
올리지 않는다. 과거 문서는 새 필드가 없을 때 아래 기본값으로 읽고, 더 새 스키마 버전과 알 수
없는 필수 프리셋 ID는 파일을 변경하지 않은 채 거부한다. FFmpeg 문자열, 글꼴 대체 경로, 입력
장치 ID, 임시 파일과 위젯 상태는 저장하지 않는다.

| 값 | 타입 또는 안정 ID | 기본값과 범위 |
| --- | --- | --- |
| 클립 페이드 | `fade_in_ns`, `fade_out_ns` | `0`, 각각 0 이상이며 합이 클립 길이 이하 |
| 내레이션 더킹 | `off`, `light`, `medium`, `strong` | `off`, 내레이션 클립만 허용 |
| 전체 믹서 | `original`, `music`, `narration` | 각 `AudioLevel(100)`, 0~100 |
| 화면 배치 | `fit`, `fill` | `fit` |
| 사용자 회전 | `0`, `90`, `180`, `270` | `0` |
| 밝기 | 정수 백분율 | `0`, -100~100 |
| 시각 효과 | `none`, `warm`, `monochrome`, `vivid` | `none` |
| 텍스트 종류 | `title`, `caption`, `credits` | `caption` |
| 텍스트 정렬 | `left`, `center`, `right` | `center` |
| 애니메이션 | `none`, `fade`, `scroll_up` | `none` |
| 전환 | `fade`, `dissolve`, `wipe_left` | 경계 값 없음 |

`TextOverlay`는 내용, `TextStyle`의 글꼴 계열·12~200 크기·굵기·RGB 색·윤곽 색·정렬,
0~10000 정수 정규화 위치와 애니메이션을 묶는다. 기본 글꼴은 `Malgun Gothic`, 흰 글자와
검정 윤곽이다. 빈 내용도 편집 상태로 보존하지만 합성 계획에서는 레이어를 만들지 않는다.

`Transition`은 왼쪽·오른쪽 시각 클립 ID, 프리셋과 길이를 가진다. 두 ID는 현재 시각 트랙에서
유일한 인접 경계여야 하고 길이는 양쪽 클립 길이의 절반 이하이다. 이 제한은 두 source 구간과
고정 프로젝트 길이를 모두 보호한다.

## 원자적 명령과 이력

모든 지속 변경은 기존 `CommandExecutor`를 사용한다.

- `AddTextClip`은 제목을 현재 장면 시작(장면이 없으면 0), 캡션을 현재 재생 위치, 크레딧을
  프로젝트 끝 직전에 배치한다. `UpdateTextProperties`는 내용·스타일·위치·시간을 함께 바꾼다.
- `UpdateVisualProperties`는 맞춤/채움, 회전, 밝기와 효과를 한 이력으로 바꾼다.
- `UpdateTransition`은 인접 경계의 추가·교체·제거를 한 이력으로 처리한다.
- `UpdateMixerSettings`는 세 버스를 한 번에 교체한다.
- `AddRecordedNarration`은 확정 WAV의 미디어 참조와 내레이션 클립을 한 이력으로 추가한다.
  undo는 프로젝트 참조만 제거하며 사용자가 확정한 WAV는 삭제하지 않는다.

기존 이동·삭제·그룹 명령으로 인접 관계가 사라지면 같은 적용에서 전환을 정리한다. 실행기는
정리 전 전환만을 작은 역연산 값으로 보관하므로 undo에서 클립과 전환이 함께 복원된다. 검증이나
명령 적용이 실패하면 프로젝트 객체와 이력 위치는 바뀌지 않는다.

## 내레이션 녹음 파일 수명주기

`NarrationRecordingCoordinator`는 장치 백엔드를 주입받아 캡처를 작업 스레드에서 수행한다.
상태는 `idle → recording ↔ paused → finalizing → complete`이며 취소·실패·닫힘은 종단
정리 경로다. Qt 백엔드는 선택한 시스템 입력을 FFmpeg로 48 kHz, mono, signed 16-bit WAV에
기록하고 입력 수준을 UI에 전달한다. 일시 정지는 장치 스트림을 유지하면서 수신 샘플을 버린다.

녹음 시작 전에 최종 경로를 확인한다. 같은 디렉터리에 고유 임시 파일을 만들고 완료 시 WAV
헤더와 실제 프레임을 검증한 뒤 flush/fsync한다. 최종 파일은 하드 링크 생성으로 한 번만
원자적으로 게시하므로 기존 파일을 덮어쓰지 않는다. 이후 임시 링크를 제거한다. 취소, 창 닫기,
권한 거부, 장치 없음·분리, 기록 실패와 디스크 부족은 임시 파일을 제거하고 프로젝트에 아무
참조도 추가하지 않는다. UI는 오류 종류와 다음 행동을 한국어 텍스트로 표시한다.

## 오디오 합성 의미

W-06 `AudioGraph`는 영상 원본음, 음악과 내레이션을 모두 48 kHz stereo로 정규화한다. 각
소스의 최종 gain은 다음 순서의 곱이다.

```text
clip AudioLevel × track-bus AudioLevel × fade envelope × duck envelope
```

음소거는 clip gain 0과 같다. 페이드는 클립의 프로젝트 시작·끝을 기준으로 선형 적용되며 부분
미리 듣기에서도 절대 프로젝트 시간의 같은 값을 사용한다. 영상 재생 속도는 기존 W-06의
0.25~4배 `atempo` 분해 규칙을 유지한다. 피치 보존은 FFmpeg 필터의 품질 범위이며 노이즈 제거,
EQ와 전문 리타이밍은 범위 밖이다.

음소거되지 않은 내레이션 클립의 더킹 값은 같은 프로젝트 시간에서 음악 소스에만 적용된다.
목표 gain은 `light=0.65`, `medium=0.40`, `strong=0.20`이고 attack은 200 ms,
release는 500 ms 선형 램프다. 겹치는 창은 더 낮은 목표 gain이 우선한다. 미리 듣기 디코더와
MP4 출력기는 같은 `build_audio_graph`와 FFmpeg volume 표현식을 사용한다.

## 화면·텍스트·전환 합성 의미

`build_composition_plan`은 UI와 독립된 공통 불변 계획이다. 미리 보기와 출력은 같은 계획과
`composition_video_filter`를 호출한다.

1. FFmpeg가 입력 회전 메타데이터를 적용한 뒤 사용자 회전을 추가한다.
2. `fit`은 종횡비를 유지해 전체 내용을 표시하고 `#181a1f` 여백을 넣는다. `fill`은 종횡비를
   유지해 확대하고 중앙에서 넘치는 영역을 자른다.
3. 밝기와 안정 프리셋 필터를 적용한다.
4. 인접 시각 소스를 연결하고 전환을 적용한다.
5. 정규화된 텍스트 좌표를 출력 캔버스에서 계산하고 5% 안전 영역 안으로 제한한다.
6. 최종 프로젝트 길이로 자르고 타임스탬프를 0에서 시작한다.

전환은 프로젝트 길이와 오디오 시간을 줄이지 않는다. 왼쪽 장면의 마지막 프레임을 전환 길이만큼
홀드하고 원래 장면 경계부터 오른쪽 장면과 합성한다. 따라서 오른쪽 source는 원래 경계에서
시작하고 오디오는 겹치거나 당겨지지 않는다. `fade`, `dissolve`, `wipe_left`만 실행한다.

글꼴 계열은 Windows의 Malgun Gothic/Gulim/Batang 허용 목록에서 해석한다. 요청 글꼴이 없으면
가용한 첫 허용 글꼴로 대체하고 `CompositionPlan.diagnostics`에 대체 사실을 남긴다. 절대 글꼴
경로는 런타임 값일 뿐 JSON에 기록하지 않는다. `fade`는 짧은 선형 진입·퇴장, `scroll_up`은
클립 시간 동안 화면 아래에서 위로 이동한다. 캔버스 축소는 이 좌표 계산 뒤 Qt 표시 단계에서만
일어난다.

## 실패, 최신 결과와 검증

누락 시각 원본, 해석 불가능한 프리셋·글꼴·화면 크기는 타입이 있는 합성 오류다. 미리 보기
요청 키에는 프로젝트 값과 프로젝트 위치가 포함되며 새 탐색·편집 세대는 이전 FFmpeg 작업을
취소한다. 실패 결과는 정상 프레임으로 캐시하지 않는다. 출력은 W-07의 임시 MP4 검증과 원자적
게시 계약을 그대로 사용한다.

자동 검증은 다음을 포함한다.

- JSON 기본값·왕복·알 수 없는 ID 거부와 모든 명령의 undo/redo·실패 원자성
- 실제/가짜 녹음 백엔드의 상태 전이, 파일 게시와 모든 실패 정리
- 페이드 경계, 세 버스 gain, 더킹 attack/release와 실제 FFmpeg 오디오 처리
- 제목·캡션·크레딧 기본 배치, 빈 텍스트 제외, 안전 영역과 글꼴 대체
- 맞춤·채움 기하, 입력·사용자 회전, 효과 범위와 전환 정리·복원
- 작은 실제 미디어에서 공통 계획으로 만든 미리 보기 PNG와 MP4 대표 픽셀 동등성
- W-01~W-08 회귀와 Qt UI 계약

## 범위 경계

실제 파형·프록시 생성과 캐시 수명주기는 W-10의 [DESIGN-0012](design-0012-recovery-background-contract.md)에서 구현됐다. 전문 색보정, 모션 그래픽 편집기, 노이즈
감소·EQ, 속도 램핑, 사용자 필터 문자열과 효과 플러그인은 구현하지 않는다. W-09의 추가 필드는
기존 스키마 의미를 바꾸지 않았으므로 새 ADR은 필요하지 않다.
