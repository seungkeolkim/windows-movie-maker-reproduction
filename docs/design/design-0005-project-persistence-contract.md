## 목적과 범위

W-03은 W-01의 불변 `Project` 그래프와 W-02의 원본 스트림 메타데이터를 하나의 UTF-8 JSON
프로젝트 파일로 저장하고 다시 연다. 새 프로젝트, 저장, 다른 이름으로 저장, 열기와 종료 전
저장 확인을 실제 Qt 흐름에 연결한다. 실제 타임라인 편집, 재생, 출력, 자동 저장, 최근
프로젝트와 다시 연결은 후속 작업이다.

프로젝트 파일에는 데이터베이스를 사용하지 않는다. 향후 앱 전역 색인이 필요해도 ADR-0004에
따라 SQLite와 DuckDB를 병행하지 않고 임베디드 엔진 하나만 선택한다.

## 파일과 스키마

- 기본 확장자는 `.mmrproj`이며 한 프로젝트는 한 JSON 문서다.
- 파일은 UTF-8, 줄바꿈이 있는 들여쓰기 JSON으로 기록한다.
- 최상위 `schema_version`은 정수 `1`이며 알 수 없는 버전은 열지 않는다.
- `project_id`, `name`, `canvas`, `media`, 네 고정 트랙과 모든 클립을 기록한다.
- 시간은 `_ns`가 붙은 정수 나노초, 비율은 양의 정수 `numerator`와 `denominator`로 기록한다.
- 미디어 스트림의 인덱스, 종류, 코덱, time base, 선택적 시작 PTS·길이 PTS, 평균 프레임률과
  샘플률을 손실 없이 기록한다.
- 선택, 포커스, 재생 위치, 패널과 타임라인 보기, 썸네일·파형·프록시, 출력 설정·진행 상태,
  저장 경로와 세션 행동 이력은 기록하지 않는다.

필수 필드의 누락, 잘못된 JSON 타입·열거형·값·참조, 중복 ID와 고정 트랙 위반은 전체 문서를
거부한다. 스키마 1에서 알 수 없는 선택 필드는 무시할 수 있지만 알려진 필드의 잘못된 값은
기본값으로 보정하지 않는다.

## 직렬화와 역직렬화

직렬화기는 도메인 객체에서 새 사전·배열만 만들며 원본 미디어를 열지 않는다. 역직렬화기는
JSON 전체를 별도 메모리 값으로 읽고 모든 하위 값을 타입 검사한 뒤 `Project` 생성자의 전체
불변식 검증까지 성공해야 결과를 반환한다. 이 과정에서 원본 경로의 존재 여부는 프로젝트
유효성과 분리한다.

원본이 없으면 `MediaReference`, 해당 클립, source in/out과 타임라인 위치를 그대로 유지한다.
UI 어댑터만 파일 존재 여부를 확인해 항목을 `누락`으로 표시한다. 열기는 원본을 복사·수정·이동
또는 삭제하지 않는다.

## 원자적 저장

저장은 다음 커밋 경계를 사용한다.

1. 대상과 같은 디렉터리에 충돌하지 않는 임시 파일을 만든다.
2. 완성된 JSON 전체를 기록한다.
3. Python 버퍼를 `flush`하고 파일 디스크립터를 `fsync`한다.
4. 파일을 닫은 뒤 `os.replace`로 대상을 한 번에 교체한다.
5. 기록, 동기화 또는 교체가 실패하면 남은 임시 파일을 제거한다.

교체 전 실패는 기존 정상 파일을 건드리지 않는다. 성공한 저장만 현재 경로를 갱신하고 dirty를
지운다. 저장과 다른 이름으로 저장의 파일 선택 취소 또는 실패는 프로젝트, 경로, 이름, dirty와
행동 이력을 바꾸지 않는다.

## 세션 교체와 저장 확인

- 새 프로젝트는 새 ID, 기본 이름, 빈 고정 트랙과 새 `CommandExecutor`로 시작한다.
- 열기는 파일 전체 파싱과 도메인 검증에 성공한 뒤에만 현재 프로젝트·경로·화면 상태를
  교체하고 새 `CommandExecutor`의 빈 이력으로 시작한다.
- 열기 취소나 실패는 현재 프로젝트, 경로, 이름, dirty와 행동 이력을 유지한다.
- 새로 만들기, 열기와 종료 전에 dirty이면 `저장`, `저장하지 않음`, `취소`를 제공한다.
- `저장`은 실제 저장 성공 뒤에만 계속한다. 경로 선택 취소나 저장 실패면 전환·종료를 멈춘다.
- `저장하지 않음`은 현재 세션을 미리 깨끗한 것으로 바꾸지 않고 요청한 전환 또는 종료만
  수행한다. `취소`는 아무 상태도 바꾸지 않는다.

Qt 어댑터는 `Ctrl+N`, `Ctrl+O`, `Ctrl+S`, `Ctrl+Shift+S`와 네이티브 파일 대화상자를 연결한다.
자동화 테스트는 열기·저장 경로 선택 함수를 주입하여 운영체제 창 없이 같은 흐름을 검증한다.

## 오류 분류와 사용자 피드백

저장·열기 서비스는 경로와 원인을 포함한 전용 예외를 사용한다. UI는 손상 JSON, 지원하지 않는
버전, 도메인 검증 실패와 파일 시스템 실패를 구분 가능한 문장으로 알리고, 기존 세션이나 정상
파일이 유지됐음을 함께 설명한다. 진단 세부사항 때문에 원본 경로를 변경하지 않는다.

## 필수 자동 검증

- 빈 프로젝트 및 모든 미디어·고정 트랙·클립 JSON 왕복
- W-02 time base, PTS, 코덱, 평균 프레임률과 샘플률 보존
- 유니코드·공백·긴 경로 저장과 열기
- 기록·동기화·교체 실패 시 기존 정상 파일 보존과 임시 파일 정리
- 손상 JSON, 잘못된 값·참조와 미지원 버전 거부 및 기존 세션 불변
- 저장·열기 파일 선택 취소와 dirty·경로·이름 불변
- 저장 확인의 저장, 저장하지 않음, 취소 분기
- 누락 원본의 구조와 편집점 보존 및 UI 누락 표시
- 저장·열기 전후 원본 미디어 해시, 크기와 수정 시간 불변
- W-01, W-02와 기존 UI 회귀
